# Phase 2 范围界定：事件影响分析 vs 管控方案优化

**重要**: 本文档澄清 Phase 2 的范围和责任边界。

---

## 核心原则

本 Phase 2 提案专注于**事件场景案例管理 UI 重构**，用于**事件影响分析工作流**。

## 两个工作流的对比

### 工作流 1：事件影响分析（Phase 2 范围）

```
事件发生 → 定义应对场景 → 创建仿真案例
           ↓
      案例列表管理（case-simulation-center.html）
           ↓
      批量启动事件响应仿真
           ↓
      实时监控进度（展开/折叠面板）
           ↓
      查看分析结果（单案例分析）
           ↓
      对比多种应对方案（对比分析）
           ↓
      评估事件影响和应对效果
```

**UI 涉及**:
- ✅ case-simulation-center.html
- ✅ analysis_viewer.html
- ✅ 进度监控、对比分析

**API 使用**:
- ✅ `/api/batch/create-from-event` (事件批次创建)
- ✅ `/api/batch/start-batch` (事件批次启动)
- ✅ `/api/v1/simulation/simulation_progress` (进度)
- ✅ `/api/v1/analysis/comparison` (对比分析)

---

### 工作流 2：管控方案优化（不在 Phase 2）

```
基础场景已知 → 定义多个控制方案
           ↓
      创建方案优化批次（独立管理）
           ↓
      批量测试多个控制方案
           ↓
      对比方案效果和成本
           ↓
      选择最优方案
           ↓
      生成方案优化建议
```

**UI 涉及**:
- ❌ 不在 Phase 2 中
- ℹ️ 属于后续的"方案优化管理"功能

**API 使用**:
- ℹ️ `/api/v1/simulation/batch-start` (优化批次启动)
- ℹ️ `/api/v1/analysis/comparison` (方案对比)
- ℹ️ 但这是后续工作，不在 Phase 2 中

---

## 关键区别

| 维度 | 事件影响分析 | 管控方案优化 |
|------|----------|-----------|
| **目标** | 理解事件影响和应对效果 | 选择最优控制方案 |
| **用户** | 应急管理部门、分析员 | 交通管理员、方案设计师 |
| **输入** | 事件 + 应对场景 | 基础场景 + 多个控制方案 |
| **输出** | 影响分析报告 | 方案优化建议 |
| **Phase 2?** | ✅ 是 | ❌ 否 |
| **时机** | 事件发生后 | 日常规划 |
| **重复周期** | 低频（事件驱动） | 高频（持续优化） |

## 实现注意事项

### ✅ 在 Phase 2 中做的事情

1. **展开/折叠式进度监控**
   - 用于**事件批次**的**实时监控**
   - 刷新频率根据展开/折叠状态调整
   - 针对事件应急场景的快速查看需求

2. **单案例分析视图**
   - 显示某个事件应对方案的**完整分析结果**
   - 包括精度分析、机理分析、性能指标等

3. **多案例对比分析**
   - 对比**同一事件的不同应对方案**
   - 帮助用户理解各方案的**相对效果**
   - 而非选择最优方案（那是后续工作）

4. **响应式设计**
   - 支持多种设备查看**事件影响分析报告**
   - 便于应急团队在现场查看分析结果

### ❌ 不在 Phase 2 中做的事情

1. **方案优化管理 UI**
   - 不实现控制方案的创建、编辑、删除
   - 不实现方案参数调整界面
   - 不实现方案效果排名和推荐

2. **控制策略管理**
   - 不实现 VSS/TEC/DHS 策略的创建和管理
   - 不实现策略参数库的维护
   - 这些属于"控制策略管理"模块

3. **性能优化算法**
   - 不实现自动生成最优方案的算法
   - 不实现约束条件下的方案搜索
   - 这属于"方案优化引擎"

4. **数据可视化和报表**
   - 不实现详细的可视化仪表板
   - 不实现自动生成 PDF/Word 报告
   - 基础分析展示即可

## 后端 API 设计注意

### API 端点的多用途性

某些 API 端点可以被多个工作流使用，但 Phase 2 只使用其中的一部分功能：

#### 例 1：`/api/v1/analysis/comparison/{batch_id}`

```javascript
// Phase 2 用法：对比事件应对方案
GET /api/v1/analysis/comparison/batch_event_8210655_20251115_100000?case_id=case_001
    → 返回该事件下不同应对方案的对比分析

// 后续工作（方案优化）的用法：对比控制方案
GET /api/v1/analysis/comparison/batch_plan_optimization_20251120_100000?case_id=baseline
    → 返回不同控制策略组合的对比分析
```

**重点**: Phase 2 不关心后续的"方案优化"工作如何使用这个 API，只需确保当前事件分析工作流能正常工作。

#### 例 2：`/api/v1/simulation/batch-start`

```javascript
// Phase 2 不直接使用（事件批次用 /api/batch/start-batch）
// 但保留给后续工作（方案优化）使用

// 后续工作可能用此 API：
POST /api/v1/simulation/batch-start
{
  "case_id": "baseline_case_001",
  "simulation_ids": ["sim_vss_001", "sim_tec_001", "sim_dhs_001"],
  "batch_type": "optimization"
}
```

**重点**: Phase 2 不使用此 API，不在范围内。

## 常见混淆点澄清

### ❓ Q1: 我们是否需要在 Phase 2 中实现方案优化功能？

**A**: 不需要。Phase 2 仅关注**事件影响分析**，不涉及**方案优化**。方案优化是后续的独立工作。

### ❓ Q2: 对比分析是用于选择最优方案吗？

**A**: 不是。Phase 2 的对比分析用于**理解不同应对方案的相对效果**，帮助用户评估事件影响。**选择最优方案**是后续"方案优化管理"的工作。

### ❓ Q3: 我们应该使用 /api/v1/simulation/batch-start 还是 /api/batch/start-batch？

**A**: 在 Phase 2 中，如果是**事件工作流**，使用 `/api/batch/start-batch`。
`/api/v1/simulation/batch-start` 是为**后续的方案优化**工作保留的，不在 Phase 2 中使用。

### ❓ Q4: 进度监控面板可以用于方案优化批次吗？

**A**: 理论上可以，因为两种批次都可能需要监控进度。但 Phase 2 的实现**优先支持事件批次**。如果后续方案优化工作需要，可以复用或扩展这个组件。

### ❓ Q5: 对比分析表的"改善"是指什么？

**A**: 指该指标与基线或其他方案相比的**相对变化**。
- 如果是时间指标（越低越好），时间减少 = 改善 = 绿色 ✓
- 如果是速度指标（越高越好），速度增加 = 改善 = 绿色 ✓
- 不是指"选择最优方案"，而是指"指标朝好的方向变化"
