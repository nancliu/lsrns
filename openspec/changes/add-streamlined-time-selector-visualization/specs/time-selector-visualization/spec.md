# 规格说明：时间选择器可视化

**能力ID**: `time-selector-visualization`
**状态**: 新增 (ADDED)
**版本**: 1.0.0

## 概述

用于显示基于时间的管控策略参数的可视化时间轴组件。为 VSS（可变限速标志）、DHS（动态硬路肩）和 TEC（收费站入口控制）策略提供带有色彩编码段的24小时时间轴可视化。

## ADDED Requirements

### Requirement: 时间轴必须渲染24小时可视化表示

**ID**: `TSV-001`
**优先级**: P0

时间轴组件 SHALL 显示24小时时间段的可视化表示，带有显示不同时间参数值的明确段。

#### 场景：将 VSS 速度步骤渲染为彩色时间轴

**给定** 一个带有速度步骤的 VSS 策略：

```json
[
  {"time_hours": 0, "speed_kmh": 100},
  {"time_hours": 7, "speed_kmh": 80},
  {"time_hours": 9, "speed_kmh": 100},
  {"time_hours": 17, "speed_kmh": 60},
  {"time_hours": 19, "speed_kmh": 100}
]
```

**当** 渲染时间轴时

**那么** 时间轴应该显示：

- 对应5个时间段的5个彩色段
- 段1 (0:00-7:00)：绿色 (#10b981) 表示 100 km/h
- 段2 (7:00-9:00)：蓝色 (#3b82f6) 表示 80 km/h
- 段3 (9:00-17:00)：绿色 (#10b981) 表示 100 km/h
- 段4 (17:00-19:00)：橙色 (#f59e0b) 表示 60 km/h
- 段5 (19:00-24:00)：绿色 (#10b981) 表示 100 km/h

**并且** 每个段的宽度应与其时间持续时间成比例

#### 场景：将 DHS 区间状态渲染为彩色时间轴

**给定** 一个带有区间的 DHS 策略：

```json
[
  {"begin_hours": 0, "end_hours": 7, "status": "CLOSED"},
  {"begin_hours": 7, "end_hours": 9, "status": "OPEN"},
  {"begin_hours": 9, "end_hours": 17, "status": "CLOSED"},
  {"begin_hours": 17, "end_hours": 19, "status": "OPEN"},
  {"begin_hours": 19, "end_hours": 24, "status": "CLOSED"}
]
```

**当** 渲染时间轴时

**那么** 时间轴应该显示：

- CLOSED 段为红色 (#ef4444)
- OPEN 段为绿色 (#10b981)
- 每个段根据 begin_hours 和 end_hours 定位

#### 场景：将 TEC 流量控制渲染为彩色时间轴

**给定** 一个带有流量区间的 TEC 策略：

```json
[
  {"begin_hours": 0, "end_hours": 6, "flow_vph": 120},
  {"begin_hours": 6, "end_hours": 10, "flow_vph": 480},
  {"begin_hours": 10, "end_hours": 17, "flow_vph": 120},
  {"begin_hours": 17, "end_hours": 20, "flow_vph": 450},
  {"begin_hours": 20, "end_hours": 24, "flow_vph": 120}
]
```

**当** 渲染时间轴时

**那么** 时间轴应该显示：

- 低流量 (<200 vph) 为绿色 (#10b981)
- 中流量 (200-399 vph) 为橙色 (#f59e0b)
- 高流量 (≥400 vph) 为红色 (#ef4444)

#### 场景：将 TEC 车型限制时间区间渲染为时间轴

**给定** 一个带有简单时间区间的 TEC 车型限制策略：

```json
[
  {"begin_hours": 0, "end_hours": 7},
  {"begin_hours": 7, "end_hours": 9},
  {"begin_hours": 9, "end_hours": 17},
  {"begin_hours": 17, "end_hours": 19},
  {"begin_hours": 19, "end_hours": 24}
]
```

**当** 渲染时间轴时

**那么** 时间轴应该显示：

- 所有区间使用统一的蓝色 (#3b82f6)
- 每个段根据 begin_hours 和 end_hours 定位
- 标签显示时间范围（如 "7:00-9:00"）

**并且** 不显示额外的参数值（因为此类型仅包含时间信息）

---

### Requirement: 时间轴必须包含小时标记

**ID**: `TSV-002`
**优先级**: P0

时间轴 SHALL 显示小时标记 (0-23) 以指示沿24小时轴的时间位置。

#### 场景：显示24个小时标记

**给定** 正在渲染时间轴

**当** 创建小时标记部分时

**那么** 时间轴应该显示：

- 24个等间距的小时标签
- 显示标签："00", "01", "02", ..., "23"
- 标签位于时间轴顶部
- 每个小时占据时间轴宽度的 1/24

---

### Requirement: 时间轴必须在段中显示值标签

**ID**: `TSV-003`
**优先级**: P0

每个时间轴段 SHALL 显示一个文本标签，指示该时间段的参数值。

#### 场景：为 VSS 显示速度标签

**给定** 一个速度为 80 km/h 的 VSS 时间轴段

**当** 渲染该段时

**那么** 该段应该显示标签文本 "80 km/h"

**并且** 标签应该：

- 白色 (#ffffff)
- 在段内居中
- 具有文本阴影以提高可读性

#### 场景：为 DHS 显示状态标签

**给定** 一个状态为 "OPEN" 的 DHS 时间轴段

**当** 渲染该段时

**那么** 该段应该显示标签文本 "OPEN" 或 "开启"

#### 场景：为 TEC 显示流量标签

**给定** 一个流量为 480 vph 的 TEC 时间轴段

**当** 渲染该段时

**那么** 该段应该显示标签文本 "480 vph" 或 "480 车/小时"

---

### Requirement: 时间轴必须与表格数据变化同步

**ID**: `TSV-004`
**优先级**: P0

当用户在表格编辑器中修改参数值时，时间轴可视化 SHALL 实时更新以反映变化。

#### 场景：表格数据变化时更新时间轴

**给定** 显示带有时间轴和表格的 VSS 策略

**当** 用户在表格中将速度值从 100 km/h 更改为 60 km/h 时

**那么** 对应的时间轴段应该：

- 颜色从绿色 (#10b981) 更改为橙色 (#f59e0b)
- 将标签文本更新为 "60 km/h"
- 应用平滑过渡动画（0.2秒持续时间）

#### 场景：添加新时间步骤时更新时间轴

**给定** 带有3个段的时间轴

**当** 用户向表格添加时间为 15:00 和速度为 70 km/h 的新行时

**那么** 时间轴应该：

- 重新渲染以显示4个段
- 在正确位置 (15:00) 插入新段
- 相应调整相邻段的宽度

#### 场景：删除时间步骤时更新时间轴

**给定** 带有5个段的时间轴

**当** 用户从表格中删除一行时

**那么** 时间轴应该：

- 重新渲染以显示4个段
- 移除对应的段
- 扩展相邻段以填补间隙

---

### Requirement: 时间轴必须与现有参数表单集成

**ID**: `TSV-005`
**优先级**: P0

时间轴组件 SHALL 与现有的参数表单系统无缝集成，而不破坏当前基于表格的编辑功能。

#### 场景：VSS 时间轴出现在表格编辑器上方

**给定** 用户在策略管理器中选择 VSS 模板

**当** 生成参数表单时

**那么** 表单应该显示：

- 顶部的时间轴可视化
- 时间轴下方的现有表格编辑器
- 两个组件在同一容器中
- 无需横向滚动

#### 场景：DHS 区间参数显示时间轴

**给定** 用户选择 DHS 模板

**当** 为 DHS 区间生成参数表单时

**那么** 时间轴应该在区间表格上方渲染

**并且** 表格编辑功能应保持不变

#### 场景：TEC 流量参数显示时间轴

**给定** 用户选择 TEC 模板

**当** 为流量控制生成参数表单时

**那么** 时间轴应该在流量控制表格上方渲染

---

### Requirement: 时间轴必须优雅地处理空或无效数据

**ID**: `TSV-006`
**优先级**: P1

时间轴组件 SHALL 处理边缘情况（如空数据、无效时间范围或格式错误的输入），而不会崩溃或破坏 UI。

#### 场景：为无数据渲染空时间轴

**给定** 参数带有空数组 `[]`

**当** 渲染时间轴时

**那么** 时间轴应该显示：

- 小时标记 (0-23)
- 带有占位符消息 "未配置时间数据" 的空时间槽部分
- 灰色背景

#### 场景：过滤掉无效时间范围

**给定** 带有无效数据的区间：

```json
[
  {"time_hours": -5, "speed_kmh": 100},     // 无效：负时间
  {"time_hours": 7, "speed_kmh": 80},        // 有效
  {"begin_hours": 10, "end_hours": 9},       // 无效：结束 < 开始
  {"begin_hours": 15, "end_hours": 30}       // 无效：结束 > 24
]
```

**当** 渲染时间轴时

**那么** 应该只显示有效的区间

**并且** 无效的区间应该作为警告记录到控制台

---

### Requirement: 时间轴必须使用一致的配色方案

**ID**: `TSV-007`
**优先级**: P0

不同参数类型的颜色映射 SHALL 保持一致和直观。

#### 场景：VSS 速度颜色映射

**给定** 各种速度值

**那么** 颜色应该映射为：

- 速度 ≥ 100 km/h → 绿色 (#10b981)
- 80 ≤ 速度 < 100 km/h → 蓝色 (#3b82f6)
- 60 ≤ 速度 < 80 km/h → 橙色 (#f59e0b)
- 速度 < 60 km/h → 红色 (#ef4444)

#### 场景：DHS 状态颜色映射

**给定** DHS 状态值

**那么** 颜色应该映射为：

- 状态 = "OPEN" → 绿色 (#10b981)
- 状态 = "CLOSED" → 红色 (#ef4444)

#### 场景：TEC 流量颜色映射

**给定** 各种流量值（每小时车辆数）

**那么** 颜色应该映射为：

- 流量 ≥ 400 vph → 红色 (#ef4444) - 高拥堵
- 200 ≤ 流量 < 400 vph → 橙色 (#f59e0b) - 中等流量
- 流量 < 200 vph → 绿色 (#10b981) - 顺畅流动

---

### Requirement: 时间轴必须具有响应性和高性能

**ID**: `TSV-008`
**优先级**: P1

时间轴 SHALL 快速渲染并保持良好性能，即使频繁更新也是如此。

#### 场景：时间轴在性能预算内渲染

**给定** 一个带有10个时间段的策略

**当** 初始渲染时间轴时

**那么** 渲染应该在 <100ms 内完成

#### 场景：时间轴更新被防抖

**给定** 用户正在快速更改表格值

**当** 在 300ms 内发生多次更改时

**那么** 时间轴应该只在更改停止后重新渲染一次

**并且** 应该跳过中间更新

---

## 交叉引用

### 相关能力

- **策略模板 (Strategy Templates)**：时间轴可视化策略模板 schema 中定义的参数
- **参数表单 (Parameter Forms)**：时间轴与现有表单生成系统集成

### 外部依赖

无（纯 JavaScript + CSS 实现）

## 实施说明

### 技术约束

1. **浏览器兼容性**：需要支持 Flexbox/CSS Grid 的现代浏览器（Chrome 90+, Firefox 88+, Safari 14+, Edge 90+）
2. **最大段数**：限制为24个段（每小时一个）以提高性能
3. **无状态设计**：时间轴模块不维护全局状态

### 代码位置

- **新模块**：`frontend/control/js/timeline_visualizer.js`
- **新样式**：`frontend/control/css/timeline.css` 或合并到 `frontend/control/styles.css`
- **修改**：`frontend/control/js/parameter_form.js`（集成点）

### 数据结构

**VSS 速度步骤**：

```typescript
interface SpeedStep {
  time_hours: number;      // 0-23
  speed_kmh: number;       // 速度值
}
```

**DHS 区间**：

```typescript
interface DHSInterval {
  begin_hours: number;     // 0-23
  end_hours: number;       // 1-24
  status: 'OPEN' | 'CLOSED';
  allowed_vehicle_types?: string[];
}
```

**TEC 流量区间**：

```typescript
interface FlowInterval {
  begin_hours: number;     // 0-23
  end_hours: number;       // 1-24
  flow_vph: number;        // 每小时车辆数
  speed_kmh?: number;      // 可选目标速度
}
```

**TEC 简单时间区间**（车型限制）：

```typescript
interface TECInterval {
  begin_hours: number;     // 0-23
  end_hours: number;       // 1-24
  // 注意：无其他参数，仅定义时间范围
}
```

## 测试要求

### 单元测试

- `timeToPercentage()` 函数准确性
- 颜色映射函数返回正确值
- 各种时间范围的时间槽宽度计算
- 边缘情况处理（空数据、无效时间）

### 集成测试

- 生成参数表单时出现时间轴
- 表格数据变化时时间轴更新
- 现有表格编辑功能无回归

### E2E 测试 (Playwright)

- 完整工作流：选择模板 → 修改表格 → 验证时间轴更新
- 跨浏览器测试（Chrome, Firefox, Edge）
- 响应式布局验证

## 可访问性考虑

- **色盲用户**：考虑除颜色外添加图案或图标（未来增强）
- **屏幕阅读器**：向时间轴段添加 ARIA 标签
- **键盘导航**：只读时间轴不需要（阶段1）

## 未来增强

- **阶段2**：交互式时间轴编辑（点击、拖动、悬停提示）
- **阶段3**：验证覆盖层（时间间隙、重叠）
- **阶段4**：导出为图像、预设模板、对比视图
