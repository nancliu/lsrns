## 🔍 根本原因分析

### 问题: 为什么测试在 120s 时仍然超时?

所有三个超时测试都在 **正好 120 秒** 时被中止，这表明:

1. **不是流程问题**: Step 1-2 都成功完成了
2. **不是选择器问题**: 参数配置页面加载成功
3. **不是功能问题**: 验证逻辑执行到了 Step 3
4. **问题点**: 在 Step 3 的 DOM 计数操作时浏览器被关闭

### 可能的原因

1. **参数表单加载性能**:
   - 参数表单可能有大量的 DOM 元素或复杂的渲染
   - 每个策略类型的参数都需要从后端加载和渲染
   - 可能需要 40-60 秒才能完全加载

2. **浏览器内存或资源**:
   - 长时间运行的 Playwright 实例可能积累内存
   - 多个连续测试可能导致资源耗尽

3. **网络或后端性能**:
   - API 响应缓慢
   - 参数查询需要数据库操作

## 💡 后续建议

### 立即优化 (优先级: 高)

#### 1. 分离为多个小测试
代替一个 120 秒的大测试，拆分为多个 30-40 秒的小测试:

```javascript
// 原: 单个 120s 测试
test('VSS 策略完整验证', async ({ page }) => {
  // Step 1, 2, 3 都在这里（耗时 60+ 秒）
});

// 新: 三个分离的测试
test('VSS Step 1: 模板选择', async ({ page }) => {
  // 只验证模板选择 (~10 秒)
});

test('VSS Step 2: 路段选择', async ({ page }) => {
  // 只验证路段查询 (~20 秒)
});

test('VSS Step 3: 参数配置', async ({ page }) => {
  // 只验证参数表单加载 (~30 秒)
});
```

#### 2. 优化网络等待策略
```javascript
// 不要用固定延时
await page.waitForTimeout(2000);

// 改用更精确的等待
await page.waitForLoadState('networkidle');
await page.waitForSelector('#param-form', { timeout: 30000 });
```

#### 3. 添加性能诊断
```javascript
console.time('参数表单加载');
await page.waitForSelector('#param-form', { timeout: 30000 });
console.timeEnd('参数表单加载');
```
