# SUMO并发性能调优指南

## 概述

当24个任务占满所有CPU（100%）时，如果想要并行运行更多SUMO任务，需要将并发比例设置为**大于1.0**（超过100%）。

## 配置建议

### 保守配置（1.2倍，推荐起步）

```json
{
  "batch_simulation": {
    "concurrent_simulations_ratio": 1.2,
    "min_concurrent": 4,
    "max_concurrent": 80
  }
}
```

**效果**：
- 24核 × 1.2 = **28-29个并发任务**
- CPU利用率：~120%
- **适用场景**：首次尝试超载，观察性能表现

### 中等配置（1.5倍，当前设置）

```json
{
  "batch_simulation": {
    "concurrent_simulations_ratio": 1.5,
    "min_concurrent": 4,
    "max_concurrent": 80
  }
}
```

**效果**：
- 24核 × 1.5 = **36个并发任务**
- CPU利用率：~150%
- **适用场景**：系统有足够内存，希望更快完成批量仿真

### 激进配置（2.0倍，需谨慎）

```json
{
  "batch_simulation": {
    "concurrent_simulations_ratio": 2.0,
    "min_concurrent": 4,
    "max_concurrent": 80
  }
}
```

**效果**：
- 24核 × 2.0 = **48个并发任务**
- CPU利用率：~200%
- **适用场景**：内存充足（128GB），I/O压力小，追求最大吞吐量

## 性能影响分析

### ✅ 优势

1. **缩短总耗时**：更多任务并行 = 更快完成批次
2. **充分利用资源**：SUMO可能有I/O等待，超线程可以更好地利用CPU空闲时间

### ⚠️ 风险与注意事项

#### 1. CPU上下文切换开销

- **问题**：超过物理核心数的任务会导致频繁上下文切换
- **影响**：单个任务执行时间可能增加10-30%
- **缓解**：监控任务完成时间，如果明显变慢，降低比例

#### 2. 内存压力

- **SUMO内存占用**：每个仿真任务约需200-500MB内存
- **当前配置**：
  - 36个任务 × 400MB = **约14.4GB**
  - 48个任务 × 400MB = **约19.2GB**
- **系统总内存**：128GB（充足）
- **建议**：保持总体内存使用 < 80GB（留出系统和其他程序空间）

#### 3. 磁盘I/O瓶颈

- **SUMO I/O操作**：
  - 读取网络文件、OD文件
  - 写入输出文件（summary.xml, tripinfo.xml等）
- **影响**：过多任务可能导致磁盘I/O队列堆积
- **缓解**：使用SSD（你已经有了NVMe SSD）

#### 4. 单个任务变慢

- **测试方法**：对比相同任务在不同并发数下的执行时间
  - 基准：24个并发时的任务时间
  - 测试：36个并发时的任务时间
  - 如果慢了 > 20%，考虑降低比例

## 推荐调优策略

### 阶段1：测试1.2倍（28-29个任务）

1. **设置配置**：
   ```json
   "concurrent_simulations_ratio": 1.2
   ```

2. **重启API服务**

3. **创建测试批次**（少量任务）

4. **监控指标**：
   - CPU利用率（应该 ~120%）
   - 内存使用（应该 < 20GB）
   - 任务平均完成时间（对比24并发时）
   - 磁盘I/O等待时间

5. **评估**：
   - ✅ 如果任务时间增加 < 10%：继续增加到1.5倍
   - ⚠️ 如果任务时间增加 10-20%：保持1.2倍或降低
   - ❌ 如果任务时间增加 > 20%：恢复到1.0倍

### 阶段2：如果1.2倍表现良好，尝试1.5倍（36个任务）

按照阶段1的步骤，继续测试和评估。

### 阶段3：激进测试（2.0倍，48个任务）

仅在以下条件全部满足时尝试：
- ✅ 内存充足（使用 < 50GB）
- ✅ 磁盘是NVMe SSD
- ✅ 1.5倍时任务时间未明显增加
- ✅ 系统整体稳定

## 监控命令

### 查看当前并发数

```powershell
python scripts\test_concurrent_config.py
```

### 实时监控资源使用

```powershell
# CPU和内存监控（每5秒刷新）
while ($true) {
    $cpu = Get-Counter '\Processor(_Total)\% Processor Time'
    $mem = Get-Counter '\Memory\Available MBytes'
    Write-Host "CPU: $($cpu.CounterSamples[0].CookedValue)% | 可用内存: $([math]::Round($mem.CounterSamples[0].CookedValue/1024, 2))GB"
    Start-Sleep -Seconds 5
}
```

### 查看SUMO进程数

```powershell
(Get-Process | Where-Object { $_.ProcessName -like "*sumo*" }).Count
```

## 配置示例对比

| 比例 | 并发任务数 | CPU利用率 | 内存需求 | 适用场景 |
|------|-----------|----------|---------|---------|
| 0.75 | 18 | 75% | ~7.2GB | 保守，系统还有其他负载 |
| 1.0 | 24 | 100% | ~9.6GB | 平衡，充分利用CPU |
| 1.2 | 28-29 | 120% | ~11.6GB | 轻度超载，首次尝试 |
| **1.5** | **36** | **150%** | **~14.4GB** | **中等超载，推荐** |
| 2.0 | 48 | 200% | ~19.2GB | 激进，需充足资源 |

## 最终建议

基于你的系统配置：
- ✅ **24核CPU**（Intel Xeon Silver 4410Y）
- ✅ **128GB内存**（充足）
- ✅ **NVMe SSD**（I/O性能好）

**推荐配置：`1.5倍`（36个并发任务）**

这个配置在：
- 缩短总耗时的同时
- 保持合理的单个任务性能
- 不会过度占用系统资源

如果发现任务变慢或系统不稳定，可以降低到1.2倍或1.0倍。
