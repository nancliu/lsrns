# DHS XML 生成修复总结

**修复日期**: 2025-11-16
**状态**: ✅ 已完成

---

## 问题描述

DHS（Dynamic Hard Shoulder / 动态硬路肩）场景生成的 `.add.xml` 文件包含**空的 `<interval>` 元素**，缺少 `<closingLaneReroute>` 子元素，导致SUMO无法正确解析DHS控制策略。

### 错误的XML格式（修复前）
```xml
<rerouter id="dhs_6120705" edges="-12680 -10376.203 ...">
  <interval begin="3300" end="5400" />  <!-- 空元素！ -->
</rerouter>
```

---

## 根本原因

`additional_generator.py` 中的 `generate_dhs_xml()` 函数尝试从SUMO网络文件读取lane IDs，但在以下场景下失败：

1. **网络文件读取失败**: 网络文件路径不正确或文件不存在
2. **Edge查询失败**: 指定的edge ID在网络文件中不存在
3. **Lane索引超出范围**: `hard_shoulder_lane_index` 超出该edge的lane数量

当 `lane_ids` 列表为空时，循环无法创建 `<closingLaneReroute>` 元素，导致生成空的 `<interval>`。

---

## 解决方案

### 1. 修改 `generate_dhs_xml()` 函数（additional_generator.py:548-598）

**改进**: 优先使用 `parameters` 中已有的 `affected_lanes` 列表，而不是尝试从网络文件读取

```python
# 获取lane IDs - 优先使用parameters中的affected_lanes
lane_ids = parameters.get("affected_lanes")

if not lane_ids:
    # 回退：从网络文件生成lane IDs
    lane_ids = _get_lane_ids_from_network(...)
```

**优势**:
- ✅ 更快：不需要解析网络文件
- ✅ 更可靠：使用已验证的lane IDs
- ✅ 向后兼容：如果没有affected_lanes，仍然可以从网络文件生成

### 2. 正确的XML结构

根据用户提供的参考示例，DHS XML应该包含：

```xml
<rerouter id="dhs_strategy_id" edges="edge1 edge2 ...">
    <!-- 应急车道关闭时段 -->
    <interval begin="3300" end="5400">
        <closingLaneReroute id="edge1_0" disallow="all"/>
        <closingLaneReroute id="edge2_0" disallow="all"/>
        ...
    </interval>

    <!-- 应急车道开放时段 -->
    <interval begin="5400" end="7200">
        <closingLaneReroute id="edge1_0" allow="all"/>
        <closingLaneReroute id="edge2_0" allow="all"/>
        ...
    </interval>
</rerouter>
```

**属性映射**:
- `status="CLOSED"` → `disallow="all"` （禁止所有车辆）
- `status="OPEN"` → `allow="all"` （允许所有车辆）

## DHS时间参数说明

### activation_schedule 字段

```json
"activation_schedule": [
    {
        "begin": 3300,                              // 开始时间（秒）

        "status": "OPEN",                           // OPEN 或 CLOSED
        "allowed_vehicle_types": ["passenger"]      // 允许的车辆类型（仅用于记录）
```

## 后续建议

### 1. 批量生成DHS场景时的参数检查

在 `scenario_service.py` 的 `_prepare_control_params()` 中确保：
- ✅ `shoulder_segments` 包含所有受影响的edge ID
- ✅ `affected_lanes` 根据 `hard_shoulder_lane_index` 正确生成
- ✅ `activation_schedule` 包含有效的时间范围和status值

### 2. 默认DHS状态

根据用户反馈"默认dhs车道是不允许车辆通行的"：
- 建议在 `_prepare_control_params()` 中设置默认 `status="CLOSED"`
- 仅在特定场景（如流量激增期间）设置 `status="OPEN"`

### 3. SUMO XML验证

可选：添加XML验证以确保生成的XML符合SUMO schema

```bash
# 验证命令
sumo -c scenario_config.sumocfg --additional-files scenario_flowsurge_dhs_*.add.xml --check-only
```
