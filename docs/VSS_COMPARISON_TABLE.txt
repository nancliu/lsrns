vss_moderate (中等控制)
├─ 独特参数数: 0 个
├─ 默认限速: 80-100 km/h
├─ 默认步骤: 4步 (07:00, 09:00, 17:00, 19:00)
├─ 应用场景: 日常高峰期流量管理
└─ 设计定位: 基础模板

vss_strict (严格控制)
├─ 独特参数数: 0 个
├─ 默认限速: 60-80 km/h (比 moderate 低 20 km/h)
├─ 默认步骤: 4步 (时间相同)
├─ 应用场景: 严重拥堵/事故处理
└─ 设计定位: 基础模板

   关键问题: vss_moderate vs vss_strict
   ├─ 参数结构: 100% 相同
   ├─ 约束条件: min=1, max=10 (相同)
   ├─ 区别点: 默认限速值 (20 km/h 差异)
   ├─ 评价: 虽然相同但场景明确不同
   │        "中等" vs "严格" 含义清晰
   │        用户易于选择
   └─ 结论: 这是合理的设计，不算"混杂"
           因为用户需要快速识别强度等级

vss_weather_based (天气应急)
├─ 独特参数数: 3 个 ★
│  ├─ weather_condition (天气类型)
│  ├─ presets (4个天气预设)
│  └─ 约束: min_steps=2 (比基础更严格)
├─ 默认限速: 120→100→80→60→100→120 km/h (大雾预设)
├─ 默认步骤: 6步 (反映天气发展过程)
├─ 应用场景: 恶劣天气期间
└─ 设计定位: 补充模板
   创新: 天气状态机制、预设库

vss_upstream_warning (上游预警)
├─ 独特参数数: 3 个 ★
│  ├─ warning_advance_minutes (3-15分钟)
│  ├─ bottleneck_location (下游位置)
│  └─ validation_rules (2条验证规则)
├─ 默认限速: 120 → 80 km/h (5分钟提前)
├─ 默认步骤: 3步 (固定：正常→降低→恢复)
├─ 约束: min_steps=3, max_steps=5 (固定模式)
├─ 应用场景: DHS开放前预警、事故前预警
└─ 设计定位: 补充模板
   创新: 事件协调机制、时间约束验证

vss_lane_differentiated (分车道控制)
├─ 独特参数数: 2 个 ★ (参数结构改变)
│  ├─ lane_configurations (多车道配置)
│  └─ generation_strategy (生成策略)
├─ 结构改变: speed_steps 采用 offset 模式
│  └─ 相对速度而非绝对值
├─ 默认配置: 2个车道 (货车道80, 小车道100)
├─ 约束: min_lanes=2, max_lanes=4
├─ 应用场景: 需要车型分离的路段
└─ 设计定位: 补充模板
   创新: 多车道参数模型、相对速度机制

绝对重复参数 (所有模板都有):
├─ affected_edges: 5/5 = 100%
├─ speed_steps: 5/5 = 100%
└─ 核心结构: 完全相同

相对参数 (部分模板):
├─ applicable_vehicle_types: 4/5 = 80%
└─ 例外: vss_lane_differentiated 通过 lane_configurations 实现

新增参数 (区分模板):
├─ weather_condition: vss_weather_based (1/5)
├─ presets: vss_weather_based (1/5)
├─ warning_advance_minutes: vss_upstream_warning (1/5)
├─ bottleneck_location: vss_upstream_warning (1/5)
├─ validation_rules: vss_upstream_warning (1/5)
├─ lane_configurations: vss_lane_differentiated (1/5)
└─ generation_strategy: vss_lane_differentiated (1/5)

总体重复度: < 5%
├─ 仅有必需的 3 个核心参数相同
├─ 每个模板都有 2-3 个独特参数
└─ 完全不是"混杂"现象

为什么 VSS 设计好而 TEC 需要优化:

✅ VSS 好的原因:
   • 基础 2 个：虽然参数结构相同，但应用场景明确不同
   • 补充 3 个：每个都有独特的新增参数和创新机制
   • 无重叠：5 个场景互不重叠，用户选择清晰
   • 文档好：每个模板的用途描述清晰

⚠️ TEC(优化前) 的问题:
   • tec_metering vs tec_metering_advanced: 参数完全相同！
   • tec_truck_ban vs tec_entrance_close: 都禁止车型，高度相似
   • tec_entrance_close vs tec_closure_complete: 结构相同只有约束不同
   • 选择困难：用户无法区分何时用哪个

✅ TEC(优化后) 解决:
   • 3 个清晰的层级：流量→车型→应急
   • 每个有明确职责，无重复
   • 分层递进，用户易于选择
