================================================================================
TECHNICAL DETAILS - WHY IT'S SO FAST
================================================================================

PROBLEM (Original):
  Single complex query: 3-table JOIN + 9-field GROUP BY + DISTINCT
  → Complex execution plan
  → Database works hard to handle the complexity
  → Result: 5440ms ✗

SOLUTION (Phase 2):
  Three simple queries:
  1. query_edges_base()      → Simple SELECT (no JOIN, no GROUP BY)
  2. get_node_types_batch()  → Batch lookup with one query
  3. get_gantry_info_batch() → Batch query + Python in-memory matching
  → Python merges results
  → Result: 539ms ✅

WHY SIMPLER QUERIES ARE FASTER:
  • Database can fully utilize indexes on single-table queries
  • No complex JOIN execution plans to optimize
  • No GROUP BY overhead
  • No DISTINCT operations
  • Network cost of 3 queries << Database complexity savings
  • Python in-memory matching is faster than BETWEEN range + JOIN
