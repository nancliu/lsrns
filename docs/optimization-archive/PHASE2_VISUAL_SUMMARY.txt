❌ PROBLEM with complex JOIN:
   SELECT ... FROM edges e
   LEFT JOIN node_units n ON e.from_junction = n.junction_id
   LEFT JOIN point_gantry g ON e.route_code = g.route_code
                               AND g.stake BETWEEN e.start AND e.end
   WHERE ... GROUP BY e.*, n.* ...

   → Creates complex execution plan
   → Database optimizer struggles with 3 tables + BETWEEN condition
   → Result: 5440ms ✗

✅ SOLUTION with separate queries:
   Query 1: SELECT ... FROM edges WHERE ...
            → Simple, uses indexes → 500ms

   Query 2: SELECT junction_id, node_type FROM node_units WHERE ...
            → Batch lookup (50 items) → 20ms

   Query 3: SELECT gantry_id, route_code, stake FROM gantry WHERE ...
            → Simple, uses indexes → 19ms

   Python: Merge results in memory → <1ms

   → Each query optimized independently
   → Python matching faster than database BETWEEN + JOIN
   → Result: 539ms ✅

Key Insight:
  1 complex query > 3 simple queries

  Database complexity cost (5440ms) >> Network cost (60ms)
  Therefore: Break complex query = WIN
