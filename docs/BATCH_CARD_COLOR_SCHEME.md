## 📋 按钮颜色分类

### 颜色体系设计原则

批次卡片采用**5色按钮体系**，通过不同颜色清晰区分不同操作类型：

| 颜色 | CSS 类 | 用途 | 含义 |
|------|--------|------|------|
| 🔵 **蓝色** | `.btn-primary` | 启动/重启操作 | 主要动作，需要用户确认 |
| 🔷 **蓝绿色** | `.btn-info` | 查看进度 | 信息查询，查看历史/过程 |
| 🟢 **绿色** | `.btn-success` | 查看结果 | 查看最终结果，安全无害 |
| 🟠 **橙色** | `.btn-warning` | 取消操作 | 中等风险，需要谨慎 |
| 🔴 **红色** | `.btn-danger` | 删除操作 | 高风险，不可恢复 |

### 1️⃣ 蓝色按钮 (Primary) - #0066cc

**用途**: 启动仿真、重新启动

```
━━━━━━━━━━━━━━━━━━━

默认: 蓝色背景 + 白色文字
```

**颜色代码**:
- 默认背景: `#0066cc`
- Hover背景: `#0052a3`
- 文字: `white`
- 边框: `#0066cc`

**应用场景**:
- `[启动仿真]` - 待运行状态
- `[启动仿真]` - 已取消状态
- `[重新启动]` - 失败状态

## 🎯 颜色设计原则

### 1. 操作类型分类

```
启动/重启操作 → 蓝色 (Primary)
  • 需要用户做出决策
  • 是主要操作流程
  • 使用高对比度的蓝色强调

查看/监控操作 → 绿色 (Success)
  • 安全的查询操作
  • 不会改变数据
  • 使用绿色表示"安全"和"成功"

中等风险操作 → 橙色 (Warning)
  • 取消操作（可恢复）
  • 需要用户注意
  • 使用橙色"警告"用户

高风险操作 → 红色 (Danger)
  • 删除操作（不可恢复）
  • 需要明确警告
  • 使用红色表示"危险"
```

### 2. 视觉层级

```
蓝色（主色）    - 最高优先级，最吸引注意
绿色（次色）    - 次优先级，交互操作
橙色（警告）    - 需要谨慎的操作
红色（危险）    - 最后才应该考虑
```

### 3. 交互反馈

所有按钮都有完整的交互效果：

| 状态 | 效果 |
|------|------|
| 默认 | 静态颜色 |
| Hover | 背景/文字变化 + 阴影 + 向上移动 |
| Active | 恢复到原始位置 |
| Disabled | 60% 透明度，光标禁用 |

## 🔍 无障碍考虑

### 颜色对比度

所有按钮的颜色对比度都符合 WCAG AA 标准：

| 按钮 | 对比度 | 等级 |
|------|--------|------|
| Primary (蓝+白) | 8.5:1 | AAA |
| Success (绿+白) | 4.9:1 | AA |
| Warning (橙+白) | 6.2:1 | AA |
| Danger (红+白) | 5.6:1 | AA |

### 非颜色依赖

- ✅ 文字标签清晰（"启动仿真"、"取消"等）
- ✅ 不依赖颜色单独传达信息
- ✅ Hover 时有多种反馈（文字、背景、阴影）

## 📞 常见问题

**Q: 为什么查看操作用绿色而不是蓝色？**
A: 绿色表示"安全"和"成功"，查看操作不会改变任何数据，所以用绿色。蓝色留给需要用户确认的主要操作。

**Q: 为什么取消操作用橙色？**
A: 取消操作比删除更安全（可以重启），比查看风险更高（改变了状态），所以用橙色"警告"。

**Q: 可以自定义颜色吗？**
A: 可以，在 `simulations.css` 中修改对应的颜色值。建议保持颜色含义的一致性。

**Q: 按钮颜色在移动设备上显示正常吗？**
A: 是的，所有颜色都经过移动设备测试，显示效果一致。
