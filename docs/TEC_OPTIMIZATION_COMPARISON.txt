1. tec_metering (基础限流)
   ├─ SUMO元素: calibrator
   ├─ 参数: entrance_edge(string), position(number), flow_intervals
   ├─ 约束: min_intervals=1
   └─ 特点: 5个时段默认配置

2. tec_metering_advanced (高级限流) ⚠️ 完全重复
   ├─ SUMO元素: calibrator
   ├─ 参数: entrance_edge(string), position(number), flow_intervals
   ├─ 约束: min_intervals=4
   ├─ 特点: 5个时段默认配置 (与#1完全相同!)
   └─ 问题: 用户无法区分何时选用

3. tec_truck_ban (货车限行)
   ├─ SUMO元素: rerouter
   ├─ 参数: entrance_edges(array), restriction_intervals, disallow_vehicle_types
   └─ 特点: 仅能禁止货车

4. tec_entrance_close (关闭) ⚠️ 高度相似
   ├─ SUMO元素: rerouter
   ├─ 参数: entrance_edges(array), closure_intervals, allowed_vehicle_types
   └─ 问题: 与#3和#5都有重叠

5. tec_closure_complete (完全关闭) ⚠️ 高度相似
   ├─ SUMO元素: rerouter
   ├─ 参数: entrance_edges(array), closure_intervals, allowed_vehicle_types
   └─ 问题: 与#4非常相似，仅约束不同

基础层 (Flow Control)
═════════════════════════════════════════════════════════════════════════════

📋 tec_flow_metering (流量控制)
   ├─ SUMO元素: calibrator
   ├─ 用途: 通过限制进入流量来管理拥堵
   ├─ 特性:
   │  ├─ 支持 1-10 个时段（用户灵活选择）
   │  ├─ 简单场景 (1-2时段) → 全天统一流量
   │  ├─ 中等场景 (2-4时段) → 高峰/非高峰分别
   │  └─ 复杂场景 (4-10时段) → 精确匹配需求曲线
   ├─ 参数:
   │  ├─ entrance_edge: 单一入口 (string)
   │  ├─ flow_intervals: [begin_hours, end_hours, vehsPerHour, target_speed]
   │  └─ position: calibrator位置 (0-1000米)
   ├─ 替代: tec_metering + tec_metering_advanced
   └─ ✅ 优势: 灵活、无冗余约束、参数清晰

限制层 (Vehicle Restriction)
═════════════════════════════════════════════════════════════════════════════

📋 tec_vehicle_restriction (车型限制)
   ├─ SUMO元素: rerouter
   ├─ 用途: 灵活地限制或禁止特定车型进入
   ├─ 特性:
   │  ├─ 两种模式: 禁止模式 | 允许模式
   │  ├─ 禁止模式: 选择要禁止的车型，其他可进
   │  └─ 允许模式: 选择要允许的车型，其他禁止
   ├─ 使用场景:
   │  ├─ 禁止货车 → disallow_mode: ["truck"]
   │  ├─ 仅允许客车 → allow_mode: ["passenger", "bus"]
   │  └─ 仅应急车 → allow_mode: ["emergency"]
   ├─ 参数:
   │  ├─ entrance_edges: 支持多个入口 (array)
   │  ├─ restriction_mode: "disallow_mode" | "allow_mode"
   │  ├─ disallow_vehicle_types: 禁止的车型列表
   │  ├─ allowed_vehicle_types: 允许的车型列表
   │  └─ restriction_intervals: [begin_hours, end_hours]
   ├─ 替代: tec_truck_ban + tec_entrance_close
   └─ ✅ 优势: 统一接口、灵活组合、覆盖所有车型管理场景

应急层 (Emergency Response)
═════════════════════════════════════════════════════════════════════════════

📋 tec_emergency_closure (紧急关闭)
   ├─ SUMO元素: rerouter
   ├─ 用途: 紧急情况完全关闭入口
   ├─ 适用情况: 仅用于应急
   │  ├─ ⚠️ 严重交通事故
   │  ├─ ⚠️ 设施故障
   │  ├─ ⚠️ 自然灾害
   │  └─ ⚠️ 其他应急情况
   ├─ 特性:
   │  ├─ 严格的5条警告信息
   │  ├─ 最佳实践指导
   │  ├─ 完全禁止（仅emergency例外）
   │  └─ 需要联系方式和时长说明
   ├─ 参数:
   │  ├─ entrance_edges: 要关闭的入口 (array)
   │  ├─ closure_intervals: [begin_hours, end_hours]
   │  ├─ closure_reason: 关闭原因
   │  ├─ expected_duration_hours: 预期时长
   │  ├─ contact_person: 负责人
   │  └─ emergency_contact: 应急电话
   ├─ 替代: tec_closure_complete (重命名)
   └─ ✅ 优势: 名称清晰、强调应急特性、安全机制完善

使用场景 → 推荐策略

1. 我想控制进入流量数量
   └─> 使用 tec_flow_metering
       示例: 限制高峰期进入流量 180-300 veh/h

2. 我想禁止某种车型
   └─> 使用 tec_vehicle_restriction (禁止模式)
       示例: 高峰期禁止货车

3. 我想仅允许某些车型
   └─> 使用 tec_vehicle_restriction (允许模式)
       示例: 仅允许客车和公交

4. 紧急情况需要关闭入口
   └─> 使用 tec_emergency_closure
       示例: 严重事故，临时关闭2小时
