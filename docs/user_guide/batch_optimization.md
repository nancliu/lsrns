# 批量优化仿真用户指南

## 概述

批量优化仿真功能允许您同时对多个交通管控方案进行仿真和对比分析，帮助您找到最优的交通管控策略组合。系统会自动并行执行多个仿真任务，并生成详细的对比报告和可视化图表。

### 主要功能

- **多方案并行仿真**: 同时运行多个管控方案的仿真，提高效率
- **随机种子支持**: 使用多个随机种子确保结果的统计稳定性
- **实时进度监控**: 查看每个仿真任务的运行状态和进度
- **结果汇总对比**: 自动计算聚合指标并生成对比报告
- **峰值曲线可视化**: Chart.js 图表展示在网车辆时序数据

## 快速开始

### 第一步：准备方案

在启动批量仿真前，您需要至少创建一个交通管控方案。

1. 前往「方案管理」页面
2. 点击「新建方案」
3. 选择需要包含的策略实例
4. 填写方案信息并保存

**提示**: 系统会自动包含基准方案（baseline_plan）作为对比基准，无需手动添加。

---

### 第二步：配置批量仿真

1. 访问 `http://localhost:8000/control/simulations.html`
2. 在「配置视图」中进行以下设置：

#### 2.1 选择案例

从下拉列表中选择已创建的仿真案例。案例包含了道路网络、OD数据等基础配置。

```
案例选择器 → 选择案例（例如：case_20251020_153045）
```

#### 2.2 选择方案

勾选需要对比的管控方案。建议选择 2-5 个方案进行对比。

```
☐ 早高峰VSS限速方案
☐ 晚高峰DHS开放方案
☐ 综合管控方案
```

**注意**: baseline_plan 会自动包含，不需要手动勾选。

#### 2.3 配置仿真参数

- **仿真次数 (num_seeds)**: 每个方案运行的次数，建议 3-5 次（默认3）
- **起始种子 (base_seed)**: 随机数生成器的起始值（默认42）
- **仿真时长**: 仿真的持续时间（小时），默认3小时

```
仿真次数: [3]  (1-10)
起始种子: [42]
```

**提示**: 
- 更多仿真次数可提高结果稳定性，但会增加总耗时
- 起始种子确保结果可重现

---

### 第三步：创建并启动批次

1. 点击「创建批次」按钮
2. 系统会创建批次并显示预估信息：
   - 总任务数 = 方案数 × 仿真次数
   - 预计完成时间
3. 点击「开始仿真」按钮启动批量仿真

```
总任务数: 9 个（3个方案 × 3次仿真）
预计耗时: 约 15-20 分钟
```

## 高级功能

### 并发控制

系统自动根据 CPU 线程数动态调整并发仿真数量（默认为 CPU线程数 × 75%）。

**示例**:
- 40核CPU: 最多同时运行 30 个仿真
- 16核CPU: 最多同时运行 12 个仿真

**手动配置** (可选):
```bash
# 设置环境变量覆盖自动计算
export MAX_CONCURRENT_SIMULATIONS=20
```

---

### 自定义仿真配置

在创建批次时，可以通过 `simulation_config` 参数自定义仿真设置。

#### 通过API配置

```json
{
  "case_id": "case_20251020_153045",
  "plan_ids": ["plan_vss_001"],
  "num_seeds": 5,
  "simulation_config": {
    "duration_hours": 4,
    "step_length": 0.5,
    "output_options": {
      "tripinfo": true,
      "summary": true,
      "edgedata": true,
      "vehroute": false
    }
  }
}
```

**参数说明**:
- `duration_hours`: 仿真时长（小时），默认3
- `step_length`: 仿真步长（秒），默认1.0
- `output_options`: 输出文件配置
  - `tripinfo`: 车辆行程信息（用于旅行时间分析）
  - `summary`: 仿真摘要（用于峰值曲线）
  - `edgedata`: 路段数据（用于路段级分析）
  - `vehroute`: 车辆路径（可选，文件较大）

---

### 时序数据分析

批量仿真支持提取和聚合 `summary.xml` 中的时序数据。

#### 数据提取

每个仿真的 `summary.xml` 包含以下时序指标：
- `time`: 时间步（秒）
- `running`: 在网车辆数
- `loaded`: 已加载车辆数
- `ended`: 已结束车辆数
- `meanSpeed`: 平均速度（m/s）

#### 聚合统计

对于每个方案的多次仿真（多个 seed），系统自动计算：
- `mean`: 平均值（各时间步的平均）
- `std`: 标准差（各时间步的标准差）
- `min`: 最小值（各时间步的最小值）
- `max`: 最大值（各时间步的最大值）

#### API调用

```bash
GET /api/v1/control/optimization/batch/{batch_id}/results?include_time_series=true
```

**响应示例**:
```json
{
  "plan_results": [
    {
      "plan_id": "plan_vss_001",
      "time_series": {
        "time": [0, 60, 120, 180, ...],
        "running_vehicles": {
          "mean": [0, 1200, 2400, 3200, ...],
          "std": [0, 50, 80, 100, ...],
          "min": [0, 1150, 2320, 3100, ...],
          "max": [0, 1250, 2480, 3300, ...]
        },
        "mean_speed": {
          "mean": [0, 12.5, 13.2, 11.8, ...],
          "std": [0, 0.5, 0.6, 0.7, ...],
          ...
        }
      }
    }
  ]
}
```

### 场景1：早高峰拥堵缓解方案对比

**目标**: 对比3种管控方案对早高峰拥堵的缓解效果

**步骤**:

1. **准备方案**
   - 方案A: 仅VSS限速（K42-K52段，50-60-80 km/h阶梯限速）
   - 方案B: 仅DHS开放（K36-K43段，7:00-9:00开放）
   - 方案C: VSS+DHS组合

2. **配置批量仿真**
   - 案例: `case_morning_peak_g4202`

   - 总任务数: 4方案 × 5次 = 20个任务

4. **分析结果**
   - 查看对比表格: 方案C的旅行时间最短（-12.5%）
   - 查看峰值曲线: 方案C的峰值车辆数最低（-8.2%）
   - 结论: VSS+DHS组合效果最佳

## 常见问题

### Q1: 为什么需要多次仿真（多个seed）？

**A**: 交通仿真中的车辆出发时间、路径选择等存在随机性。多次仿真可以：
- 减少随机波动的影响
- 提供统计置信区间（标准差）
- 确保结果的可靠性

建议至少3次，重要决策建议5-10次。

---

### Q2: 如何选择仿真时长？

**A**: 根据分析目标选择：
- **早/晚高峰分析**: 2-3小时（覆盖高峰时段）
- **全天分析**: 12-24小时
- **快速测试**: 1小时

注意：更长时长会显著增加仿真耗时。

---

### Q3: 批量仿真失败怎么办？

**A**: 检查以下方面：
1. **案例文件完整性**: 确保config、OD、路网文件存在
2. **方案XML有效性**: 确保 control.add.xml 格式正确
3. **SUMO配置**: 检查 SUMO_HOME 环境变量
4. **磁盘空间**: 确保有足够空间存储输出文件
5. **查看日志**: 检查任务的 `error` 字段获取详细错误信息

---

### Q4: 如何加速批量仿真？

**A**: 
1. **硬件升级**: 使用更多CPU核心
2. **减少仿真次数**: 降低 `num_seeds`（牺牲精度）
3. **缩短仿真时长**: 减少 `duration_hours`
4. **关闭不必要的输出**: 禁用 `edgedata`、`vehroute` 等大文件输出
5. **手动设置并发数**: 如果CPU使用率低，可通过环境变量提高并发

---

### Q5: 结果中的标准差（std）如何解读？

**A**: 
- **小标准差** (< 5%均值): 结果稳定，可信度高
- **中等标准差** (5-15%均值): 存在一定波动，建议增加仿真次数
- **大标准差** (> 15%均值): 结果不稳定，需检查方案配置或增加仿真次数

**示例**:
```
平均旅行时间: 1800 ± 50 秒  →  std = 50/1800 = 2.8%（稳定）
平均旅行时间: 1800 ± 250 秒 →  std = 250/1800 = 13.9%（需更多仿真）
```

## 最佳实践

### 1. 方案设计

✅ **推荐**:
- 先测试单一策略类型（VSS、DHS、TEC），再测试组合
- 方案之间有明确的对比维度（如限速值、开放时长）
- 合理命名方案，便于结果分析

❌ **避免**:
- 一次对比过多方案（>10个），结果难以分析
- 方案配置过于相似，难以区分效果
- 忽略基准方案，无法评估改善效果

---

### 2. 仿真配置

✅ **推荐**:
- 使用3-5个随机种子确保稳定性
- 仿真时长覆盖目标时段（如早高峰6:00-9:00）
- 启用必要的输出文件（tripinfo, summary）

❌ **避免**:
- 仅使用1个种子（结果不可靠）
- 仿真时长过短（无法观察完整效果）
- 启用所有输出选项（浪费存储和计算资源）

---

### 3. 结果分析

✅ **推荐**:
- 关注多个指标（旅行时间、速度、峰值车辆数）
- 结合峰值曲线观察时序变化
- 计算相对基准的改善百分比

❌ **避免**:
- 仅关注单一指标（可能忽略副作用）
- 忽略标准差（可能误判不稳定结果）
- 不考虑实施成本（如DHS需要路段条件）
