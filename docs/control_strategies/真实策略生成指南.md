# 真实交通控制策略生成指南

## 一、概述

本指南说明如何基于实际交通数据和路网信息，创建科学合理的交通控制策略实例。

## 二、当前演示策略的局限性

### 现有22个演示策略存在的问题：

| 问题类型 | 具体表现 | 影响 |
|---------|---------|------|

### 步骤2：选择目标路段

#### 2.1 路段选择标准

**✓ 必须满足的条件：**
- 路段连续性（通过junction连接关系验证）
- 功能一致性（车道数、限速相近）
- 长度适中：
  - VSS：2-5公里
  - DHS：5-10公里
  - TEC：单个入口匝道

#### 2.2 从数据库查询路段

```sql
-- 查询G4202顺时针方向K10-K15区间的连续路段
SELECT
    edge_id,
    start_stake,
    end_stake,
    length,
    num_lanes,
    from_junction,
    to_junction
FROM dim.sim_network_edges
WHERE route_code = 'G4202'
  AND route_direction = 'CW'  -- 顺时针
  AND start_stake >= 10.0
  AND end_stake <= 15.0
ORDER BY start_stake;

-- 验证路段连续性
-- 确保前一段的 to_junction = 后一段的 from_junction
```

#### 2.3 查询入口匝道（TEC策略专用）

```sql
-- 查询入口匝道
SELECT
    edge_id,
    from_junction,
    to_junction,
    length,
    route_code
FROM dim.sim_network_edges
WHERE function = 'entrance'  -- 或根据实际字段判断
  AND route_code = 'G4202'
ORDER BY start_stake;
```

### 步骤3：确定策略类型和参数

#### 3.1 VSS（可变限速）策略

**适用场景：** 路段拥堵，速度波动大

**参数配置模板：**
```json
{
  "strategy_id": "strategy_real_vss_001",
  "strategy_name": "G4202北段K10-K15早高峰可变限速",
  "description": "针对K10-K15路段早高峰拥堵问题，采用分时段限速控制",
  "template_id": "vss_moderate",
  "strategy_type": "VSS",
  "configured_params": {
    "affected_edges": [
      "-12345",  // 从数据库查询获得
      "-12346",
      "-12347"
    ],
    "speed_steps": [
      {"time_hours": 6, "speed_kmh": 120},   // 早高峰前：正常限速
      {"time_hours": 7, "speed_kmh": 100},   // 高峰初期：预警降速
      {"time_hours": 8, "speed_kmh": 80},    // 高峰期：严格限速
      {"time_hours": 9, "speed_kmh": 100},   // 高峰末期：恢复
      {"time_hours": 10, "speed_kmh": 120}   // 平峰期：正常限速
    ],
    "applicable_vehicle_types": ["passenger", "truck"]
  },
  "tags": ["G4202", "早高峰", "可变限速", "真实策略"],
  "created_at": "2025-10-26T00:00:00Z",
  "updated_at": "2025-10-26T00:00:00Z",
  "created_by": "traffic_engineer",
  "status": "active"
}
```

**参数选择科学依据：**

| 参数 | 计算方法 | 数据来源 |
|------|---------|---------|
| affected_edges | 拥堵路段 + 上游1km | EdgeData分析 |
| speed_kmh | 自由流速度 × (0.6~0.8) | 历史仿真速度分布 |
| time_hours | 拥堵开始时间 ±1小时 | EdgeData时序分析 |

**参考标准：**
- 《公路交通安全设施设计规范》JTG D81-2017

#### 3.2 TEC（收费站/入口管控）策略

**适用场景：** 入口匝道排队过长，主线容量接近饱和

**参数配置模板：**
```json
{
  "strategy_id": "strategy_real_tec_001",
  "strategy_name": "G4202东入口早高峰流量控制",
  "description": "针对东入口匝道早高峰排队问题，采用分时段流量限制",
  "template_id": "tec_flow_metering",
  "strategy_type": "TEC",
  "configured_params": {
    "entrance_edge": "-10592",  // 单个入口匝道edge_id
    "position": 0,              // 控制点位置（0=起点，匝道长度=终点）
    "flow_intervals": [
      {
        "begin_hours": 0,
        "end_hours": 7,
        "vehsPerHour": 600,     // 平峰期：正常通行
        "target_speed": 20
      },
      {
        "begin_hours": 7,
        "end_hours": 9,
        "vehsPerHour": 240,     // 早高峰：严格限流（60%削减）
        "target_speed": 10      // 降低速度，增加排队缓冲
      },
      {
        "begin_hours": 9,
        "end_hours": 17,
        "vehsPerHour": 600,     // 白天平峰
        "target_speed": 20
      },
      {
        "begin_hours": 17,
        "end_hours": 19,
        "vehsPerHour": 360,     // 晚高峰：中度限流（40%削减）
        "target_speed": 15
      },
      {
        "begin_hours": 19,
        "end_hours": 24,
        "vehsPerHour": 600,     // 夜间平峰
        "target_speed": 20
      }
    ]
  },
  "tags": ["G4202", "入口控制", "流量限制", "早高峰", "真实策略"],
  "created_at": "2025-10-26T00:00:00Z",
  "updated_at": "2025-10-26T00:00:00Z",
  "created_by": "traffic_engineer",
  "status": "active"
}
```

**参数选择科学依据：**

| 参数 | 计算公式 | 说明 |
|------|---------|------|
| vehsPerHour | (主线容量 - 主线当前流量) × 0.9 | 保留10%安全余量 |
| target_speed | 10-20 km/h | 匝道建议速度，影响排队密度 |
| 削减比例 | 30-60% | 根据主线拥堵程度调整 |

**计算示例：**
```
假设：
- 主线设计容量：4500 veh/h
- 早高峰主线流量：4000 veh/h
- 匝道平峰流量：600 veh/h

计算：
入口允许流量 = (4500 - 4000) × 0.9 = 450 × 0.9 = 405 veh/h

但考虑其他入口，实际设置：240-360 veh/h
```

|------|---------|-------------|

#### 5.4 参数优化

```

调整：
  - VSS: 限速值降低5-10 km/h
  - TEC: 流量限制增加10-20%
  - DHS: 延长开放时段30-60分钟

如果：排队长度增加
调整：
  - TEC: 放宽流量限制10-15%
  - 优化时间段边界（±30分钟）

如果：速度波动过大
调整：
  - VSS: 增加中间档位，平滑过渡
  - 调整路段范围（增减1-2个edge）
```

## 六、常见问题FAQ

### Q1: 如何获取历史仿真数据？
**A:** 运行已有case，生成EdgeData分析结果：
```bash
POST /api/v1/analysis/edgedata
{
  "case_id": "case_001",
  "simulation_id": "sim_001"
}
```

### Q2: 如何确定路段是否连续？
**A:** 查询数据库验证junction连接：
```sql
-- 检查路段A的to_junction是否等于路段B的from_junction
SELECT
    a.edge_id as edge_a,
    a.to_junction,
    b.edge_id as edge_b,
    b.from_junction,
    CASE WHEN a.to_junction = b.from_junction THEN '连续' ELSE '不连续' END as status
FROM dim.sim_network_edges a
JOIN dim.sim_network_edges b ON a.to_junction = b.from_junction
WHERE a.edge_id = '-9292' AND b.edge_id = '-8014';
```

### Q3: 限速值如何选择？
**A:** 基于历史仿真的自由流速度：
```
1. 查询EdgeData分析结果，找到非拥堵时段的平均速度（自由流）
2. 拥堵时段限速 = 自由流速度 × 0.6 ~ 0.8
3. 示例：自由流100km/h → 拥堵限速60-80km/h
```

### Q4: TEC流量限制如何计算？
**A:** 基于主线容量和当前流量：
```
入口允许流量 = (主线设计容量 - 主线当前流量) × 安全系数

其中：
- 主线设计容量：查询路段设计文档或按 2000 veh/h/lane 估算
- 主线当前流量：从EdgeData分析结果获取
- 安全系数：0.8-0.9（保留10-20%缓冲）
```

### Q5: DHS策略何时可以使用？
**A:** 必须满足所有安全条件：
```
✓ 流量/容量比 > 0.9（接近饱和）
✓ 速度 < 60 km/h（已拥堵）
✓ 路段长度 ≥ 5km（足够长）
✓ 应急车道宽度 ≥ 3.0m（符合标准）
✓ 近期无重大事故（安全优先）
```
