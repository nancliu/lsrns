## 1. 概述

### 1.1 研究背景

在智能交通管控系统中，如何根据真实的交通流数据自动生成有效的管控方案是一个核心挑战。传统的人工设计方案方式存在以下问题：

- **效率低下**: 需要交通工程师逐一分析拥堵点，手动配置策略参数
- **主观性强**: 依赖个人经验，难以保证方案的一致性和最优性
- **响应滞后**: 面对动态变化的交通状况，无法快速调整方案
- **协同困难**: 多策略组合时，参数协调复杂，容易出现冲突

本研究基于 OD_SIM 系统的实践经验，提出了一套**从基准数据到可落地应用方案的自动生成流程**，涵盖拥堵识别、策略选择、参数优化、协同配置等关键环节。

### 1.2 研究目标

1. **建立系统化的方案生成方法论**: 从简单单策略到复杂多策略协同的完整路径
2. **验证数据驱动的可行性**: 基于真实基准数据（baseline.baseflow_pattern_gantry）自动识别拥堵点和策略需求
3. **形成可复用的算法框架**: 支持不同路段、不同拥堵模式的方案自动化生成
4. **评估自动化程度**: 分析当前可实现的自动化范围和需人工干预的环节

### 1.3 Plan架构定位

**核心理念**: Plan（控制方案）是**通用的、可复用的交通管控模板**，而不是针对单个Case的一次性配置。

#### Plan vs Case 关系

```
┌─────────────────────────────────────────────────────────────┐
│  Plan（控制方案）- 通用模板                                   │
│  ┌───────────────────────────────────────────────────────┐  │
│  │ • 描述拥堵场景模式（如"早高峰拥堵"）                    │  │
│  │ • 定义策略组合（如VSS+DHS）                            │  │
│  │ • 配置协同机制（时序、空间、参数耦合）                  │  │
│  │ • 预期效果类型（速度提升100-200%）                    │  │
│  │ • 适用条件（速度<30 km/h，持续2h+）                   │  │
│  └───────────────────────────────────────────────────────┘  │
│                                                               │
│                     可应用于 ↓                                │
│                                                               │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐       │
│  │ Case A      │   │ Case B      │   │ Case C      │       │
│  │ (10月数据)  │   │ (11月数据)  │   │ (12月数据)  │       │
│  └─────────────┘   └─────────────┘   └─────────────┘       │
│                                                               │
│  同一个Plan在不同Case上验证，accumulate validation_records   │
└─────────────────────────────────────────────────────────────┘
```

#### Plan的核心属性

| 属性类别 | 属性名 | 描述 | 是否绑定Case |
|---------|-------|------|-------------|
| **标识信息** | plan_id | 语义化ID，如`plan_vss_morning_peak_simple` | ❌ 不绑定 |
| | plan_name | 描述性名称 | ❌ 不绑定 |
| **策略配置** | strategy_ids | 引用的策略ID列表 | ❌ 不绑定 |
| | strategy_coordination | 策略协同机制（时序、空间、参数） | ❌ 不绑定 |
| **适用条件** | applicable_conditions | 拥堵模式、时间窗口、严重度阈值 | ❌ 不绑定（通用） |
| | target_scenario | 目标场景描述（通用表述） | ❌ 不绑定 |
| **预期效果** | expected_effects | 改善类型和范围（如"提升100-200%"） | ❌ 不绑定（范围） |
| **验证记录** | validation_records | 在哪些Case上验证过，效果如何 | ✅ 记录Case关联 |

#### Plan的设计原则

1. **通用性优先**: Plan描述"拥堵场景模式"而非"具体路段拥堵事件"
2. **可复用性**: 同一Plan可应用到多个满足条件的Case
3. **参数化**: 具体参数（如限速值）可根据Case数据微调
4. **验证积累**: 每次在新Case上验证后，更新validation_records
5. **渐进完善**: Plan随着验证次数增加而不断优化

#### 典型应用流程

```python
# 1. 用户分析新的Case数据，识别拥堵模式
congestion_pattern = analyze_case_data(case_id="case_202511_week1")
# Result: "早高峰拥堵，速度25 km/h，持续3小时"

# 2. 系统匹配适用的Plan
matched_plans = match_plans_by_conditions(congestion_pattern)
# Result: [plan_vss_morning_peak_simple, ...]

# 3. 用户选择Plan并应用到Case
apply_plan_to_case(
    plan_id="plan_vss_morning_peak_simple",
    case_id="case_202511_week1"
)

# 4. 运行仿真并记录验证结果
validation_result = run_simulation_and_validate(...)

# 5. 更新Plan的validation_records
update_plan_validation_records(
    plan_id="plan_vss_morning_peak_simple",
    validation_result=validation_result
)
```

### 2.2 核心算法模块

#### 模块 1: 拥堵识别算法 (Congestion Identification)

**输入**: 基准数据 (gantry_id, time_hour, avg_speed_kmh, flow_veh_per_hour)
**输出**: 拥堵点列表 (congestion_points) 及其特征

**算法逻辑**:

```python
def identify_congestion_points(baseline_data, config):
    """
    拥堵识别算法

    Parameters:
    - baseline_data: DataFrame with columns [gantry_id, time_hour, avg_speed_kmh, flow_veh_per_hour]
    - config: {
        'speed_thresholds': {
            'severe': 20,      # 严重拥堵: <20 km/h
            'moderate': 40,    # 中度拥堵: 20-40 km/h
            'light': 60        # 轻度拥堵: 40-60 km/h
        },
        'duration_threshold': 2,  # 持续时长阈值 (小时)
        'flow_threshold': 200     # 流量阈值 (veh/hr)
    }

    Returns:
    - List of congestion points with severity scores
    """

    congestion_points = []

    # 1. 按门架分组，计算统计量
    for gantry_id, group in baseline_data.groupby('gantry_id'):
        # 1.1 识别低速时段
        severe_hours = group[group['avg_speed_kmh'] < config['speed_thresholds']['severe']]
        moderate_hours = group[
            (group['avg_speed_kmh'] >= config['speed_thresholds']['severe']) &
            (group['avg_speed_kmh'] < config['speed_thresholds']['moderate'])
        ]

        # 1.2 计算拥堵持续时长
        severe_duration = len(severe_hours)
        moderate_duration = len(moderate_hours)

        # 1.3 满足持续时长阈值
        if severe_duration >= config['duration_threshold'] or \
           moderate_duration >= config['duration_threshold']:

            # 1.4 计算严重度评分 (0-100)
            severity_score = calculate_severity_score(
                min_speed=group['avg_speed_kmh'].min(),
                max_flow=group['flow_veh_per_hour'].max(),
                duration_hours=severe_duration + moderate_duration * 0.5
            )

            congestion_points.append({
                'gantry_id': gantry_id,
                'min_speed': group['avg_speed_kmh'].min(),
                'max_flow': group['flow_veh_per_hour'].max(),
                'severe_duration': severe_duration,
                'moderate_duration': moderate_duration,
                'severity_score': severity_score,
                'peak_hours': severe_hours['time_hour'].tolist()
            })

    # 2. 按严重度评分降序排序
    congestion_points.sort(key=lambda x: x['severity_score'], reverse=True)

    return congestion_points


def calculate_severity_score(min_speed, max_flow, duration_hours):
    """
    拥堵严重度评分算法

    综合考虑:
    - 最低速度 (权重 40%)
    - 最大流量 (权重 30%)
    - 持续时长 (权重 30%)

    Returns: 0-100的评分，100为最严重
    """

    # 速度分 (速度越低分数越高)
    # 参考: 0 km/h = 100分, 60 km/h = 0分
    speed_score = max(0, 100 - min_speed / 0.6)

    # 流量分 (流量越大分数越高，但设置上限)
    # 参考: 500 veh/hr = 100分
    flow_score = min(100, max_flow / 5.0)

    # 时长分 (持续越久分数越高)
    # 参考: 12小时 = 100分
    duration_score = min(100, duration_hours / 0.12)

    # 加权求和
    severity_score = (
        speed_score * 0.4 +
        flow_score * 0.3 +
        duration_score * 0.3
    )

    return round(severity_score, 2)
```

#### 模块 2: 策略选择引擎 (Strategy Selection Engine)

**输入**: 拥堵点特征 (min_speed, max_flow, duration, road_type)
**输出**: 推荐策略类型及模板

**规则库**:

```python
def select_strategies(congestion_point, available_strategies):
    """
    策略选择规则引擎

    Parameters:
    - congestion_point: {
        'min_speed': float,
        'max_flow': float,
        'severe_duration': int,
        'road_type': str,  # 'ring' or 'linear'
        'has_hard_shoulder': bool,
        'has_entrance_control': bool
    }
    - available_strategies: List of available strategy templates

    Returns:
    - List of recommended strategies with priority
    """

    recommended = []

    # 规则 1: 速度过低 (<30 km/h) → VSS (可变限速)
    if congestion_point['min_speed'] < 30:
        vss_template = select_vss_template(congestion_point['min_speed'])
        recommended.append({
            'type': 'VSS',
            'template': vss_template,
            'priority': 'P0',
            'reason': f"最低速度{congestion_point['min_speed']} km/h，需限速稳定交通流"
        })

    # 规则 2: 流量大 (>300 veh/hr) + 有应急车道 → DHS (动态硬路肩)
    if congestion_point['max_flow'] > 300 and congestion_point['has_hard_shoulder']:
        recommended.append({
            'type': 'DHS',
            'template': 'dhs_peak_hours',
            'priority': 'P0',
            'reason': f"流量{congestion_point['max_flow']} veh/hr，开放应急车道增加通行能力"
        })

    # 规则 3: 持续时长长 (>6小时) + 有入口 → TEC (入口流量控制)
    if congestion_point['severe_duration'] > 6 and congestion_point['has_entrance_control']:
        recommended.append({
            'type': 'TEC',
            'template': 'tec_strict',
            'priority': 'P0',
            'reason': f"拥堵持续{congestion_point['severe_duration']}小时，需上游入口限流"
        })

    # 规则 4: 多策略协同判断
    if len(recommended) >= 2:
        recommended.append({
            'type': 'COORDINATION',
            'strategies': [s['type'] for s in recommended],
            'priority': 'P0',
            'reason': "多因素拥堵，需多策略协同管控"
        })

    return recommended


def select_vss_template(min_speed):
    """
    根据最低速度选择VSS模板严格程度
    """
    if min_speed < 20:
        return 'vss_strict'      # 严格限速: 40-50 km/h
    elif min_speed < 30:
        return 'vss_moderate'    # 中等限速: 60-80 km/h
    else:
        return 'vss_light'       # 轻度限速: 80-100 km/h
```

**策略组合规则**:

| 拥堵特征 | 推荐策略组合 | 优先级 | 应用场景 |
|---------|-------------|-------|---------|
| 低速 (<20 km/h) | VSS 单策略 | P0 | 早高峰短时拥堵 |
| 低速 + 高流量 | VSS + DHS | P0 | 晚高峰持续拥堵 + 通行能力不足 |
| 低速 + 高流量 + 长时长 | VSS + DHS + TEC | P0 | 全天拥堵 + 入口过载 |
| 中速 (20-40 km/h) | VSS 单策略 | P1 | 次要拥堵点 |

#### 模块 3: 参数优化算法 (Parameter Optimization)

**VSS 参数优化**:

```python
def optimize_vss_parameters(congestion_point, target_speed_improvement=100):
    """
    VSS 可变限速参数优化

    Parameters:
    - congestion_point: 拥堵点特征
    - target_speed_improvement: 目标速度提升百分比 (%)

    Returns:
    - speed_steps: List of {time_hours, speed_kmh}
    """

    min_speed = congestion_point['min_speed']
    peak_hours = congestion_point['peak_hours']

    # 1. 计算目标速度
    target_speed = min_speed * (1 + target_speed_improvement / 100)

    # 2. 根据严重程度确定限速档位
    if min_speed < 20:
        # 严重拥堵: 50 km/h 限速
        control_speed = 50
    elif min_speed < 30:
        # 中度拥堵: 60 km/h 限速
        control_speed = 60
    else:
        # 轻度拥堵: 80 km/h 限速
        control_speed = 80

    # 3. 生成时间步骤
    speed_steps = []

    # 平峰期: 正常速度
    speed_steps.append({'time_hours': 0, 'speed_kmh': 100})

    # 高峰期前1小时: 预警速度
    pre_peak_hour = min(peak_hours) - 1
    speed_steps.append({'time_hours': pre_peak_hour, 'speed_kmh': 80})

    # 高峰期: 严格限速
    speed_steps.append({'time_hours': min(peak_hours), 'speed_kmh': control_speed})

    # 高峰期结束: 恢复
    post_peak_hour = max(peak_hours) + 1
    speed_steps.append({'time_hours': post_peak_hour, 'speed_kmh': 80})

    # 夜间: 正常速度
    speed_steps.append({'time_hours': 23, 'speed_kmh': 100})

    return speed_steps
```

**DHS 参数优化**:

```python
def optimize_dhs_parameters(congestion_point):
    """
    DHS 应急车道开放参数优化

    Returns:
    - intervals: List of {begin_time, end_time, allow_vehicles}
    """

    peak_hours = congestion_point['peak_hours']

    intervals = []

    # 1. 平峰期: 关闭应急车道
    if min(peak_hours) > 0:
        intervals.append({
            'begin_time': 0,
            'end_time': min(peak_hours) * 3600,  # 转换为秒
            'allow_vehicles': ['emergency']
        })

    # 2. 高峰期: 开放应急车道
    intervals.append({
        'begin_time': min(peak_hours) * 3600,
        'end_time': (max(peak_hours) + 1) * 3600,
        'allow_vehicles': ['passenger', 'bus', 'truck', 'emergency']
    })

    # 3. 高峰期后: 关闭应急车道
    if max(peak_hours) < 23:
        intervals.append({
            'begin_time': (max(peak_hours) + 1) * 3600,
            'end_time': 86400,  # 24小时
            'allow_vehicles': ['emergency']
        })

    return intervals
```

**TEC 参数优化**:

```python
def optimize_tec_parameters(congestion_point, reduction_target=0.6):
    """
    TEC 入口流量控制参数优化

    Parameters:
    - reduction_target: 流量削减目标 (0-1之间，0.6表示削减60%)

    Returns:
    - flow_steps: List of {begin_time, end_time, veh_per_hour, speed}
    """

    max_flow = congestion_point['max_flow']
    peak_hours = congestion_point['peak_hours']

    flow_steps = []

    # 1. 计算限流值
    controlled_flow = max_flow * (1 - reduction_target)

    # 2. 平峰期: 正常通行
    normal_flow = max_flow * 1.0  # 不限流
    flow_steps.append({
        'begin_time': 0,
        'end_time': min(peak_hours) * 3600,
        'veh_per_hour': normal_flow,
        'speed': 15  # m/s
    })

    # 3. 高峰期: 严格限流
    flow_steps.append({
        'begin_time': min(peak_hours) * 3600,
        'end_time': (max(peak_hours) + 1) * 3600,
        'veh_per_hour': controlled_flow,
        'speed': 8  # m/s (更低速度，强制限流)
    })

    # 4. 高峰期后: 恢复
    flow_steps.append({
        'begin_time': (max(peak_hours) + 1) * 3600,
        'end_time': 86400,
        'veh_per_hour': normal_flow,
        'speed': 15
    })

    return flow_steps
```

#### 模块 4: 多策略协同算法 (Multi-Strategy Coordination)

**时序协调**:

```python
def coordinate_time_sequences(strategies):
    """
    多策略时序协调算法

    确保多个策略的激活时间序列协调一致

    Parameters:
    - strategies: List of {type, parameters}

    Returns:
    - coordinated_strategies: 协调后的策略列表
    """

    # 1. 提取所有策略的关键时间点
    all_time_points = set()
    for strategy in strategies:
        if strategy['type'] == 'VSS':
            for step in strategy['parameters']['speed_steps']:
                all_time_points.add(step['time_hours'])
        elif strategy['type'] == 'DHS':
            for interval in strategy['parameters']['intervals']:
                all_time_points.add(interval['begin_time'] / 3600)
                all_time_points.add(interval['end_time'] / 3600)
        elif strategy['type'] == 'TEC':
            for flow in strategy['parameters']['flow_steps']:
                all_time_points.add(flow['begin_time'] / 3600)
                all_time_points.add(flow['end_time'] / 3600)

    # 2. 按时间顺序排序
    sorted_times = sorted(all_time_points)

    # 3. 定义协调规则
    # 规则: TEC应在VSS之前或同时激活，DHS应在VSS激活后
    coordination_rules = {
        'activation_order': ['TEC', 'VSS', 'DHS'],
        'time_offsets': {
            'TEC_to_VSS': -1,  # TEC提前1小时
            'VSS_to_DHS': 1     # DHS延后1小时
        }
    }

    # 4. 调整各策略的时间参数
    coordinated_strategies = []
    for strategy in strategies:
        if strategy['type'] == 'TEC':
            # TEC需要最早激活
            strategy['activation_time'] = min(sorted_times) + coordination_rules['time_offsets']['TEC_to_VSS']
        elif strategy['type'] == 'VSS':
            # VSS正常激活
            strategy['activation_time'] = min(sorted_times)
        elif strategy['type'] == 'DHS':
            # DHS延后激活
            strategy['activation_time'] = min(sorted_times) + coordination_rules['time_offsets']['VSS_to_DHS']

        coordinated_strategies.append(strategy)

    return coordinated_strategies
```

```python
def coordinate_spatial_coverage(strategies, road_network):
    """
    多策略空间覆盖协调算法

    确保多个策略作用于正确的路段范围

    Parameters:
    - strategies: List of {type, parameters}
    - road_network: 路网拓扑结构

    Returns:
    - spatial_plan: 空间协调方案
    """

    spatial_plan = {
        'upstream': None,    # 上游控制区 (TEC)
        'midstream': None,   # 中游控制区 (VSS)
        'downstream': None   # 下游控制区 (DHS)
    }

    # 1. 识别拥堵路段的上下游关系
    congestion_edges = get_congestion_edges(road_network)

    # 2. 为每个策略分配空间范围
    for strategy in strategies:
        if strategy['type'] == 'TEC':
            # TEC控制上游入口
            upstream_entrances = find_upstream_entrances(congestion_edges, road_network)
            spatial_plan['upstream'] = {
                'control_type': 'TEC',
                'edges': upstream_entrances,
                'description': '上游入口限流，源头控制车辆数量'
            }

        elif strategy['type'] == 'VSS':
            # VSS控制拥堵路段本身
            spatial_plan['midstream'] = {
                'control_type': 'VSS',
                'edges': congestion_edges,
                'description': '主线限速控制，稳定交通流'
            }

        elif strategy['type'] == 'DHS':
            # DHS也在拥堵路段，但需检查是否有应急车道
            dhs_eligible_edges = filter_hard_shoulder_edges(congestion_edges, road_network)
            spatial_plan['downstream'] = {
                'control_type': 'DHS',
                'edges': dhs_eligible_edges,
                'description': '应急车道开放，增加通行能力'
            }

    # 3. 检查空间冲突
    # VSS和DHS可能作用于相同路段，需要确保参数协调
    if spatial_plan['midstream'] and spatial_plan['downstream']:
        if set(spatial_plan['midstream']['edges']) & set(spatial_plan['downstream']['edges']):
            # 有重叠，需要调整VSS限速以适应DHS开放后的通行能力
            adjust_vss_for_dhs(strategies)

    return spatial_plan


def adjust_vss_for_dhs(strategies):
    """
    当DHS开放时，调整VSS限速值

    逻辑: DHS开放后车道数增加，VSS限速可以适当提高
    """
    vss_strategy = next(s for s in strategies if s['type'] == 'VSS')
    dhs_strategy = next(s for s in strategies if s['type'] == 'DHS')

    # 找到DHS开放的时间段
    dhs_open_times = [
        (interval['begin_time'] / 3600, interval['end_time'] / 3600)
        for interval in dhs_strategy['parameters']['intervals']
        if 'passenger' in interval['allow_vehicles']
    ]

    # 调整VSS在该时间段的速度
    for step in vss_strategy['parameters']['speed_steps']:
        for begin, end in dhs_open_times:
            if begin <= step['time_hours'] < end:
                # DHS开放期间，VSS可以提高10 km/h
                step['speed_kmh'] = min(step['speed_kmh'] + 10, 100)
```

**参数耦合优化**:

```python
def optimize_coupled_parameters(strategies, baseline_data):
    """
    多策略参数耦合优化

    考虑策略之间的相互影响，优化参数配置

    Parameters:
    - strategies: List of coordinated strategies
    - baseline_data: 基准数据

    Returns:
    - optimized_strategies: 优化后的策略
    """

    optimized_strategies = strategies.copy()

    # 1. TEC-VSS耦合优化
    # 原则: TEC限流值应使主线流量保持在VSS限速下的安全容量范围内
    if has_strategy_types(strategies, ['TEC', 'VSS']):
        tec_strategy = next(s for s in strategies if s['type'] == 'TEC')
        vss_strategy = next(s for s in strategies if s['type'] == 'VSS')

        # 计算VSS限速下的道路容量
        for vss_step in vss_strategy['parameters']['speed_steps']:
            road_capacity = calculate_road_capacity(
                speed_limit=vss_step['speed_kmh'],
                num_lanes=3,  # 假设3车道
                lane_width=3.75  # m
            )

            # 调整TEC限流值，不超过道路容量的80%
            for tec_flow in tec_strategy['parameters']['flow_steps']:
                if are_overlapping_times(vss_step, tec_flow):
                    tec_flow['veh_per_hour'] = min(
                        tec_flow['veh_per_hour'],
                        road_capacity * 0.8
                    )

    # 2. VSS-DHS耦合优化
    # 原则: DHS开放后，VSS限速应适当提高以充分利用增加的车道
    if has_strategy_types(strategies, ['VSS', 'DHS']):
        vss_strategy = next(s for s in optimized_strategies if s['type'] == 'VSS')
        dhs_strategy = next(s for s in strategies if s['type'] == 'DHS')

        for dhs_interval in dhs_strategy['parameters']['intervals']:
            if 'passenger' in dhs_interval['allow_vehicles']:
                # DHS开放时间段
                dhs_open_hours = range(
                    dhs_interval['begin_time'] // 3600,
                    dhs_interval['end_time'] // 3600
                )

                # 调整VSS速度
                for vss_step in vss_strategy['parameters']['speed_steps']:
                    if vss_step['time_hours'] in dhs_open_hours:
                        # 增加10-15 km/h，但不超过80 km/h (安全限制)
                        vss_step['speed_kmh'] = min(vss_step['speed_kmh'] + 10, 80)

    return optimized_strategies


def calculate_road_capacity(speed_limit, num_lanes, lane_width):
    """
    计算道路通行能力 (简化模型)

    使用Highway Capacity Manual (HCM)公式
    """
    # 基础容量 (pcu/h/lane)
    base_capacity = 2200

    # 速度修正系数
    speed_factor = speed_limit / 100  # 归一化

    # 车道宽度修正系数
    width_factor = lane_width / 3.75  # 标准车道宽度

    # 总容量
    total_capacity = base_capacity * num_lanes * speed_factor * width_factor

    return total_capacity
```

### 4.3 完全自动化流程设计

```python
class AutoPlanGenerator:
    """
    交通管控方案全自动生成器

    实现从基准数据到可部署方案的端到端自动化
    """

    def __init__(self, db_connection, road_network, strategies_pool):
        self.db = db_connection
        self.network = road_network
        self.strategies = strategies_pool
        self.congestion_analyzer = CongestionAnalyzer()
        self.strategy_selector = StrategySelector()
        self.plan_composer = PlanComposer()

    def generate_all_plans(self, batch_id='20251013_20251019'):
        """
        一键生成所有优先级的方案

        Returns:
        - List of generated plans (simple, composite, complex)
        """

        # Step 1: 加载基准数据
        baseline_data = self.load_baseline_data(batch_id)

        # Step 2: 识别拥堵点
        congestion_points = self.congestion_analyzer.identify_congestion_points(
            baseline_data,
            config={
                'speed_thresholds': {'severe': 20, 'moderate': 40},
                'duration_threshold': 2,
                'flow_threshold': 200
            }
        )

        # Step 3: 按优先级排序
        prioritized = sorted(
            congestion_points,
            key=lambda x: x['severity_score'],
            reverse=True
        )

        # Step 4: 为每个拥堵点生成方案
        all_plans = []

        for i, point in enumerate(prioritized[:5]):  # TOP 5拥堵点
            # 4.1 生成简单方案
            simple_plan = self.plan_composer.generate_simple_plan(point, self.strategies)
            all_plans.append(simple_plan)

            # 4.2 如果满足条件，生成复合方案
            if point['max_flow'] > 300 and self.network.has_hard_shoulder(point['edges']):
                composite_plan = self.plan_composer.generate_composite_plan(point, self.strategies)
                all_plans.append(composite_plan)

            # 4.3 如果满足条件，生成复杂方案
            if point['severe_duration'] > 6 and self.network.has_entrance_control(point['edges']):
                complex_plan = self.plan_composer.generate_complex_plan(point, self.strategies)
                all_plans.append(complex_plan)

        # Step 5: 保存所有方案
        for plan in all_plans:
            self.save_plan(plan)

        # Step 6: 生成总览报告
        self.generate_summary_report(all_plans)

        return all_plans

    def load_baseline_data(self, batch_id):
        """从数据库加载基准数据"""
        query = f"""
        SELECT
            gantry_id,
            route_code,
            stake_km,
            time_hour,
            avg_speed_kmh,
            flow_veh_per_hour
        FROM baseline.baseflow_pattern_gantry
        WHERE batch_id = '{batch_id}'
        ORDER BY gantry_id, time_hour
        """
        return pd.read_sql(query, self.db)

    def save_plan(self, plan):
        """保存方案到文件系统"""
        plan_dir = f"control_data/plans/{plan['plan_id']}"
        os.makedirs(plan_dir, exist_ok=True)

        # 保存元数据
        with open(f"{plan_dir}/plan_metadata.json", 'w', encoding='utf-8') as f:
            json.dump(plan['metadata'], f, ensure_ascii=False, indent=2)

        # 保存策略引用
        with open(f"{plan_dir}/strategy_refs.json", 'w', encoding='utf-8') as f:
            json.dump(plan['strategy_ids'], f, ensure_ascii=False, indent=2)

        # 保存SUMO配置
        with open(f"{plan_dir}/control.add.xml", 'w', encoding='utf-8') as f:
            f.write(plan['additional_xml'])
```

## 5. 实施建议与未来优化方向

### 5.1 短期实施建议 (1-3个月)

1. **建立拥堵点数据库**
   - 定期 (每周) 运行拥堵识别算法
   - 维护历史拥堵数据，识别长期趋势
   - 建立拥堵点优先级队列

2. **完善路网属性数据**
   - 补充应急车道信息 (has_hard_shoulder, shoulder_width)
   - 标注入口控制点 (entrance_edges, ramp_metering_capable)
   - 更新路段容量参数 (num_lanes, lane_width, design_capacity)

3. **实现半自动化流程**
   - 自动生成候选方案
   - 人工审核关键参数
   - 自动生成SUMO配置文件

4. **建立方案评估体系**
   - 运行基准仿真 (无管控)
   - 运行策略仿真 (有管控)
   - 自动计算改善指标 (速度提升%, 拥堵时长减少%)

### 5.2 中期优化方向 (3-6个月)

1. **参数自适应优化**
   - 基于仿真结果反馈，自动调整策略参数
   - 使用遗传算法/贝叶斯优化寻找最优参数组合
   - 建立参数-效果映射模型

2. **多目标优化**
   - 同时优化速度提升、流量增加、拥堵时长减少
   - 考虑碳排放、燃油消耗等环保指标
   - 平衡管控效果与实施成本

3. **动态方案调整**
   - 根据实时交通数据动态调整策略参数
   - 实现"预测-响应"机制 (预测未来1小时拥堵，提前激活策略)
   - 支持临时事件的快速响应 (事故、施工)

4. **方案库建设**
   - 积累不同场景的成功方案
   - 建立"拥堵模式-最优方案"知识库
   - 支持相似场景的快速检索和复用

### 5.3 长期研究方向 (6-12个月)

1. **机器学习增强**
   - 训练拥堵预测模型 (LSTM, Transformer)
   - 学习策略效果预估模型 (避免仿真，直接预估改善效果)
   - 强化学习优化策略参数 (DQN, PPO)

2. **区域协同管控**
   - 跨路段的策略协同 (如G4202整条环线的协同管控)
   - 多路线的流量平衡 (G5与S8的流量分流)
   - 城市级交通管控网络

3. **仿真-现实闭环**
   - 实际部署策略，采集实施效果数据
   - 对比仿真预测与实际效果，校准仿真模型
   - 建立"仿真-部署-评估-优化"闭环

4. **标准化与推广**
   - 制定交通管控方案自动生成标准
   - 开发可视化方案设计工具
   - 推广到其他城市和路网

### 6.1 研究成果
