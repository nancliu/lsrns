## 📌 概述

批量仿真监控系统提供分层级的仿真管理和结果分析功能，支持多方案对比、基准方案强制包含、统一输出配置、以及结果快速可视化。

### 核心功能

| 功能 | 说明 | 用途 |
|---|---|---|
| **案例分组** | 按案例分层显示批次 | 快速定位特定案例的批次 |
| **统一配置** | 所有方案使用相同output_level | 确保公平比较 |
| **基准包含** | 自动包含baseline_plan | 保证有对标数据 |
| **结果分析** | 自动计算改进率 | 快速评估策略效果 |
| **可视化展示** | 表格 + 图表 | 直观对比多方案性能 |

## 🎯 使用场景

### 场景1：批量评估多个控制策略

**问题**: 如何快速对比3个控制策略相对基准方案的效果？

**解决方案**:
1. 在"配置"标签创建批次，选择基准方案 + 3个控制策略
2. 系统自动包含基准方案作为对标
3. 等待仿真完成后，在"结果"标签查看对比表格
4. 通过改进率百分比判断哪个策略最有效

### 场景2：快速批量筛选（最小化输出）

**问题**: 需要快速筛选出最有前景的策略，不需要详细数据

**解决方案**:
1. 创建批次时选择 `output_level: minimal`
2. 系统只生成 summary.xml + E1门架数据
3. 仿真速度快 50% 左右
4. 通过基础指标初步筛选后，再用标准/完整输出做深入分析

### 场景3：多轮快速迭代

**问题**: 需要对同一案例运行多轮批次，每轮评估不同的策略组合

**解决方案**:
- 利用案例分组功能快速切换不同批次
- 每个批次保留完整历史和结果
- 支持批次取消、删除等操作
- 批次列表可按状态筛选（运行中/已完成/失败）

## 📖 功能详解

### 1. 案例分组与批次列表

#### 界面布局

在"批次监控"标签中，批次按案例分层显示：

```
┌─ 案例001 [最近更新: 2小时前]
│  ├─ 批次1 (已完成) - 3个方案 × 3轮 = 9个仿真
│  ├─ 批次2 (运行中) - 2个方案 × 5轮 = 10个仿真
│  └─ 批次3 (失败) - 重新启动
│
├─ 案例002 [最近更新: 昨天]
│  ├─ 批次4 (已完成) - 4个方案 × 3轮 = 12个仿真
│  └─ 批次5 (已完成) - 2个方案 × 3轮 = 6个仿真
│
└─ 案例003 [最近更新: 3天前]
   └─ 批次6 (已完成) - 1个方案 × 1轮 = 1个仿真
```

#### 交互操作

**展开/收起案例组**
- 点击案例组标题栏展开/收起该案例的所有批次
- 状态记录在会话中（刷新后重置）

**排序和筛选**
- **按状态筛选**: 全部 / 运行中 / 已完成 / 失败 / 已取消
- **按创建时间排序**: 最近创建 / 最近完成 / 耗时最长
- 筛选结果跨案例生效

**批次卡片操作**
- 点击"启动"启动已暂停的批次
- 点击"进度"查看实时进度和任务详情
- 点击"结果"查看批次结果和对比分析
- 点击"⋯"菜单查看更多操作（取消、删除）

**卡片进度显示** (Phase 8.4新增)
- 运行中的批次卡片上显示绿色进度条
- 进度条显示0-100%的完成百分比
- 每5秒自动刷新一次，无需手动操作
- 批次完成时自动更新状态标签

**手动刷新** (Phase 8.4新增)
- 批次列表头部的"🔄 刷新"按钮
- 点击立即重新加载所有批次
- 用于更新可能延迟的进度数据

### 2. 统一配置一致性

#### 输出级别选择

在"配置"标签创建批次时，选择输出级别：

| 级别 | 包含文件 | 特点 | 仿真速度 | 用途 |
|---|---|---|---|---|
| **minimal** | summary.xml<br/>E1门架数据 | 最轻量 | ⚡ 快 | 快速筛选 |
| **standard** | minimal +<br/>tripinfo.xml<br/>edgedata.xml | 均衡 | 🔄 中等 | 详细分析（推荐） |
| **full** | 所有输出文件<br/>完整细节 | 最详细 | 🐢 慢 | 研究/演示 |

**关键保证**:
- ✅ 同一批次内所有方案使用相同output_level
- ✅ 确保各方案在相同条件下对标
- ✅ 系统自动验证配置一致性

#### 随机种子配置

**每个方案仿真次数**: 1-10次（默认3次）

**示例**:
```
案例：3个方案，4轮随机
种子序列：66, 67, 68, 69
总任务数：3方案 × 4轮 = 12个仿真任务

第一轮: baseline(66), control_001(66), control_002(66) → 相同种子，公平对标
第二轮: baseline(67), control_001(67), control_002(67) → 添加随机性
第三轮: baseline(68), control_001(68), control_002(68)
第四轮: baseline(69), control_001(69), control_002(69)
```

**种子预览**: 创建批次前自动计算并显示种子序列

### 3. 基准方案强制包含

#### 自动保证机制

即使用户未选择基准方案，系统也会自动包含：

```
用户选择:     plan_control_001, plan_control_002
系统生成:     baseline_plan, plan_control_001, plan_control_002
任务列表:     3个方案被创建，baseline排在首位
```

#### UI提示

- "配置"标签上方显示蓝色提示框说明baseline自动包含
- 方案列表中基准方案显示<span style="background:#e8f5e9; color:#2e7d32; padding:2px 6px; border-radius:3px;">基准</span>标签
- 基准方案的复选框禁用（不可取消）

#### 结果中的标记

在结果对比表中，基准方案一行显示为:
- **样式**: 灰色背景、加粗字体
- **改进率列**: 显示"-"（基准本身无改进率）
- **其他方案**: 相对基准的改进率百分比

### 4. 结果分析与可视化

#### 结果页面布局

"结果"标签包含两大部分：

**（1）对比表格**
```
┌────────────────┬──────────────┬────────────────┬──────────┐
│ 指标           │ 基准值       │ 控制方案1      │ 改进率   │
├────────────────┼──────────────┼────────────────┼──────────┤
│ 平均速度       │ 25.5 km/h    │ 30.2 km/h      │ +18.4%   │
│ 平均等待时间   │ 120 s        │ 98 s           │ +18.3%   │
│ 电子传送数     │ 12           │ 5              │ +58.3%   │
└────────────────┴──────────────┴────────────────┴──────────┘
```

- **绿色 (+)**：改进（正向指标如速度↑，或负向指标如等待时间↓）
- **红色 (-)**：恶化（与改进相反）

**（2）性能对比图表**

使用Chart.js生成交互式柱状图：
- X轴：各方案（基准 + 控制方案们）
- Y轴：指标值
- 柱状图颜色：
  - 灰色：基准
  - 绿色：改进
  - 红色：恶化

#### 改进率计算方法

**方向1 - 越大越好** (e.g., 平均速度):
```
改进率 = (测试值 - 基准值) / 基准值 × 100%
```

**方向2 - 越小越好** (e.g., 等待时间):
```
改进率 = (基准值 - 测试值) / 基准值 × 100%
```

#### 导出功能

点击"导出结果"按钮下载CSV文件，包含：
- 所有指标和基准值
- 各方案测试值
- 改进率百分比
- 便于后续数据分析

## 🔧 工作流示例

### 完整的批量评估流程

#### 第1步：创建批次

1. 进入"批量仿真" → "配置"标签
2. 选择案例：`案例_G4202_绕城西南`
3. 选择方案：
   - `strategy_vss_001`（可变限速）
   - `strategy_vss_dhs_001`（限速+硬路肩）
4. 配置参数：
   - 输出级别：`standard`
   - 随机种子数：`3`
5. 点击"创建批次"

**系统动作**:
- ✅ 自动添加 `baseline_plan`
- ✅ 生成统一 `simulation_config.json`
- ✅ 创建6个仿真任务 (3方案 × 2轮)
- ✅ 返回批次ID: `batch_20251103_140000`

#### 第2步：启动仿真

1. 在"批次监控"找到该批次卡片
2. 点击"启动"按钮

**系统动作**:
- ✅ 后台启动所有任务
- ✅ 批次状态变为"运行中"

#### 第3步：实时监控（可选）

1. 点击"进度"按钮
2. 查看实时进度条和任务列表
3. 每10秒自动刷新（可手动刷新）

**显示内容**:
- 总进度百分比
- 已完成/运行中/失败任务数
- 每个任务的状态和耗时
- 预计完成时间

#### 第4步：查看结果

仿真完成后（通常30-60分钟）：

1. 点击"结果"按钮，自动加载结果
2. 查看对比表格：
   - baseline_plan平均速度 25.5 km/h
   - strategy_vss_001: 28.3 km/h (+11.0%)
   - strategy_vss_dhs_001: 31.8 km/h (+24.7%)
3. 查看柱状图确认可视化效果
4. 如需深入分析，点击"导出结果"下载CSV

**结论**: VSS+DHS策略比单独VSS策略效果更好 (+24.7% vs +11.0%)

## 💡 最佳实践

### 1. 输出级别选择

| 场景 | 推荐级别 | 理由 |
|---|---|---|
| 快速筛选 | minimal | 仿真速度快，指标足够初步判断 |
| 日常分析 | standard | 均衡速度和数据完整性 |
| 学术论文 | full | 详细数据便于深入分析 |
| 不确定 | standard | 默认选择，适合大多数场景 |

### 2. 随机种子数设置

| 场景 | 推荐轮数 | 理由 |
|---|---|---|
| 快速测试 | 1 | 最快但结果可能不稳定 |
| 初步验证 | 3 | 推荐默认值，平衡统计意义和速度 |
| 严格评估 | 5-10 | 增加统计可信度，耗时较长 |

### 3. 批次管理建议

- ✅ **命名清晰**: 在创建前思考好策略组合，方便后续回顾
- ✅ **及时导出**: 完成后立即导出CSV，便于归档
- ✅ **分阶段执行**: 先minimal快速筛选，再standard深入分析
- ✅ **保留历史**: 至少保留最后3个完成的批次，便于比较

### 4. 性能优化

- 📊 **案例数量多时**: 利用筛选功能关注特定案例
- 📊 **批次很多时**: 按"最近创建"或"最近完成"排序，快速定位
- 📊 **监控等待时**: 先处理其他工作，系统会自动更新进度

## ⚠️ 常见问题

### Q1: 基准方案没有改进率，这正常吗？

**A**: 正常的。改进率是相对于基准计算的，基准本身的改进率定义为"-"（不适用）。

### Q2: 不同批次的结果能否比较？

**A**: 不建议直接比较。最好的做法是将所有要比较的策略放在同一批次（同一随机种子序列），确保公平。

### Q3: 可以中途修改运行中的批次配置吗？

**A**: 不可以。需要取消当前批次，新建一个批次。已完成的任务不会受影响。

### Q4: 为什么批次一直显示"运行中"？

**A**:
1. 仿真耗时较长（标准配置通常30-60分钟）
2. 某个SUMO进程可能卡住 → 点击"进度"查看详情
3. 系统故障 → 检查API服务日志

### Q5: 能否手动修改simulation_config.json中的参数？

**A**: 不建议。这会破坏配置一致性。应该取消批次，修改参数后重新创建。

### Q6: 结果中某个方案的数据为空怎么办？

**A**: 该方案的仿真可能失败。点击"进度"查看该方案的任务状态和错误消息。
