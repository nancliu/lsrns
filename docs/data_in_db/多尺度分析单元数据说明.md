# 多尺度分析单元数据说明

## 概述

本文档描述了基于SUMO仿真路网数据生成的多尺度分析单元体系，包含节点层、设施层、路网层三个尺度的分析单元，为多尺度交通网络评估提供数据基础。

**应用目标**: 这些表主要用于**仿真结果的交通运行状态分析**，特别适用于分析**事件或管控措施对交通网络的影响**，支持交通管控策略的效果评估和优化决策。

## 数据统计总览

| 尺度层级 | 单元数量 | 数据表 | 主要特征 |
|---------|---------|--------|----------|
| **节点层** | 9,491个 | `dim.multiscale_node_units` | 七类节点单元 |
| **设施层** | 271个 | `dim.multiscale_facility_units` | 三类交通设施 |
| **路网层** | 8个 | `dim.multiscale_network_units` | 三种网络类型 |

## 一、节点层分析单元

### 1.1 数据表结构

- **表名**: `dim.multiscale_node_units`
- **坐标系**: WGS84 (EPSG:4326)
- **主键**: `unit_id` (varchar(50), NOT NULL)
- **主要字段**:
  - `unit_id`: 节点单元唯一标识（主键）
  - `unit_name`: 节点单元名称（varchar(100)）
  - `junction_id`: 原始节点ID（varchar(50)）
  - `node_type`: 节点类型（七类节点，varchar(20)）
  - `route_code`: 所属路线代码（varchar(20)）
  - `section_code`: 所属路段代码（varchar(50)）
  - `demonstration_id`: 示范段ID（integer）
  - `stake_number`: 桩号位置（numeric(10,3)）
  - `geometric_center`: 几何中心点（PostGIS geometry类型）
  - `in_edge_count`: 入边数量（integer）
  - `out_edge_count`: 出边数量（integer）
  - `total_in_lanes`: 总入车道数（integer）
  - `total_out_lanes`: 总出车道数（integer）
  - `connected_edge_ids`: 连接边ID列表（ARRAY类型）
  - `connected_facilities`: 连接设施信息（JSONB）
  - `analysis_metrics`: 分析指标（JSONB）
  - `created_at`: 创建时间（timestamp，默认CURRENT_TIMESTAMP）

### 1.2.1 JSONB字段详解

#### `connected_facilities` 字段

- **作用**: 存储与该节点连接的设施单元信息
- **数据结构**: 包含连接设施的ID、名称、类型等基本信息
- **典型应用**: 分析节点与设施的关联关系，识别关键连接点

#### `analysis_metrics` 字段

- **作用**: 存储节点的综合分析指标
- **主要指标**:
  - `time_metrics`: 时间相关指标（自由流时间、平均时间等）
  - `speed_metrics`: 速度相关指标（平均速度、速度方差等）
  - `health_metrics`: 健康度指标（延误概率、节点健康评分、容量利用率等）
  - `distance_metrics`: 距离相关指标（平均边长度、总连接长度等）
  - `topology_metrics`: 拓扑指标（是否终端节点、车道变化指数、连通性指数等）
- **典型应用**: 节点性能评估、瓶颈识别、容量分析

### 1.4 典型使用方法

```sql
-- 查询特定路线的结构节点
SELECT unit_id, junction_id, node_type, stake_number, 
       in_edge_count, out_edge_count, total_in_lanes, total_out_lanes
FROM dim.multiscale_node_units 
WHERE route_code = 'G5' 
  AND node_type IN ('diverging', 'merging', 'lane_increase', 'lane_decrease')
ORDER BY stake_number;

-- 统计各路线节点密度和车道容量
SELECT route_code, 
       COUNT(*) as total_nodes,
       COUNT(CASE WHEN node_type IN ('diverging', 'merging', 'lane_increase', 'lane_decrease') THEN 1 END) as structural_nodes,
       ROUND(AVG(total_in_lanes)::numeric, 1) as avg_in_lanes,
       ROUND(AVG(total_out_lanes)::numeric, 1) as avg_out_lanes
FROM dim.multiscale_node_units 
GROUP BY route_code
ORDER BY structural_nodes DESC;

-- 分析节点连接复杂度
SELECT node_type,
       COUNT(*) as count,
       ROUND(AVG(in_edge_count + out_edge_count)::numeric, 1) as avg_connections,
       ROUND(AVG(total_in_lanes + total_out_lanes)::numeric, 1) as avg_total_lanes
FROM dim.multiscale_node_units 
GROUP BY node_type
ORDER BY avg_connections DESC;

-- 分析节点健康度指标
SELECT unit_id, junction_id, node_type,
       (analysis_metrics->'health_metrics'->>'node_health_score')::numeric as health_score,
       (analysis_metrics->'health_metrics'->>'capacity_utilization')::numeric as capacity_util,
       (analysis_metrics->'health_metrics'->>'delay_probability')::numeric as delay_prob
FROM dim.multiscale_node_units 
WHERE (analysis_metrics->'health_metrics'->>'node_health_score')::numeric < 0.7
ORDER BY health_score;

-- 查询节点的时间性能指标
SELECT unit_id, junction_id,
       (analysis_metrics->'time_metrics'->>'avg_free_flow_time')::numeric as avg_time,
       (analysis_metrics->'speed_metrics'->>'avg_free_flow_speed')::numeric as avg_speed,
       (analysis_metrics->'distance_metrics'->>'avg_edge_length')::numeric as avg_edge_length
FROM dim.multiscale_node_units 
WHERE node_type IN ('diverging', 'merging')
ORDER BY avg_time DESC;
```

## 二、设施层分析单元

### 2.1 数据表结构

- **表名**: `dim.multiscale_facility_units`
- **坐标系**: WGS84 (EPSG:4326)
- **主键**: `facility_id` (varchar(50), NOT NULL)
- **主要字段**:
  - `facility_id`: 设施唯一标识（主键）
  - `facility_name`: 设施名称（varchar(100)）
  - `facility_type`: 设施类型（三类，varchar(30)）
  - `route_code`: 所属路线代码（varchar(20)）
  - `section_code`: 所属路段代码（varchar(50)）
  - `demonstration_id`: 示范段ID（integer）
  - `start_stake`: 起始桩号（numeric(10,3)）
  - `end_stake`: 终止桩号（numeric(10,3)）
  - `node_count`: 包含的节点数量（integer）
  - `edge_count`: 包含的边数量（integer）
  - `node_ids`: 包含的节点ID列表（ARRAY类型）
  - `edge_ids`: 包含的边ID列表（ARRAY类型）
  - `geometric_boundary`: 几何边界（PostGIS geometry类型）
  - `facility_metrics`: 设施指标（JSONB）
  - `created_at`: 创建时间（timestamp，默认CURRENT_TIMESTAMP）
  - `updated_at`: 更新时间（timestamp）

### 2.1.1 JSONB字段详解

#### `facility_metrics` 字段

- **作用**: 存储设施单元的综合分析指标和评级信息
- **主要指标**:
  - `node_count`: 包含的节点数量
  - `stake_range`: 桩号范围（公里）
  - `merging_count`, `diverging_count`, `lane_decrease_count`, `lane_increase_count`: 各类型节点数量
  - `complexity_score`: 复杂度评分
  - `facility_rating`: 设施评级（整体评分、优先级、性能等级）
  - `aggregated_metrics`: 聚合指标
    - `node_metrics`: 节点级指标（终端节点数、平均车道变化、连通性等）
    - `time_metrics`: 时间指标（平均自由流时间、总自由流时间）
    - `facility_health`: 设施健康度（延误概率、容量利用率、整体健康评分）
    - `distance_metrics`: 距离指标（平均边长度、设施长度、总连接长度）
    - `complexity_metrics`: 复杂度指标（节点多样性、拓扑密度、结构复杂度）
- **典型应用**: 设施性能评估、优先级排序、容量规划、健康度监控

### 2.4 典型使用方法

```sql
-- 查询特定类型的设施
SELECT facility_id, facility_name, route_code, 
       ST_AsText(geometric_boundary) as boundary_wkt
FROM dim.multiscale_facility_units 
WHERE facility_type = 'interchange'
  AND route_code = 'G4202'
ORDER BY facility_name;

-- 分析设施空间分布密度
SELECT route_code, facility_type,
       COUNT(*) as count,
       ROUND(AVG(ST_Area(ST_Transform(geometric_boundary, 3857))/1000000)::numeric, 2) as avg_area_km2

       array_agg(j.category ORDER BY j.stake_number) as node_categories

LEFT JOIN dim.sim_network_junctions j ON j.junction_id = ANY(f.node_ids)
WHERE f.facility_type = 'interchange'
GROUP BY f.facility_id, f.facility_name, f.facility_type
ORDER BY node_count DESC;

-- 分析设施性能评级
SELECT facility_id, facility_name, facility_type,
       (facility_metrics->'facility_rating'->>'overall_score')::numeric as overall_score,
       (facility_metrics->'facility_rating'->>'priority_level') as priority_level,
       (facility_metrics->'facility_rating'->>'performance_grade') as performance_grade,
       (facility_metrics->>'complexity_score')::numeric as complexity_score
FROM dim.multiscale_facility_units 
WHERE facility_type = 'interchange'
ORDER BY (facility_metrics->'facility_rating'->>'overall_score')::numeric DESC;

-- 查询设施健康度指标
SELECT facility_id, facility_name, facility_type,
       (facility_metrics->'aggregated_metrics'->'facility_health'->>'overall_health_score')::numeric as health_score,
       (facility_metrics->'aggregated_metrics'->'facility_health'->>'delay_probability')::numeric as delay_prob,
       (facility_metrics->'aggregated_metrics'->'facility_health'->>'capacity_utilization')::numeric as capacity_util
FROM dim.multiscale_facility_units 
WHERE (facility_metrics->'aggregated_metrics'->'facility_health'->>'overall_health_score')::numeric < 0.8
ORDER BY health_score;

-- 分析设施复杂度指标
SELECT facility_id, facility_name, facility_type,
       (facility_metrics->>'node_count')::int as node_count,
       (facility_metrics->'aggregated_metrics'->'complexity_metrics'->>'node_diversity')::int as node_diversity,
       (facility_metrics->'aggregated_metrics'->'complexity_metrics'->>'structural_complexity')::numeric as structural_complexity
FROM dim.multiscale_facility_units 
WHERE facility_type = 'interchange'
ORDER BY (facility_metrics->>'node_count')::int DESC;
```

## 三、路网层分析单元

### 3.1 数据表结构

- **表名**: `dim.multiscale_network_units`
- **主键**: `network_id` (varchar(50), NOT NULL)
- **主要字段**:
  - `network_id`: 路网单元唯一标识（主键）
  - `network_name`: 路网单元名称（varchar(100)）
  - `network_type`: 路网类型（三种，varchar(30)）
  - `route_codes`: 包含的路线代码列表（ARRAY类型）
  - `facility_count`: 设施数量（integer）
  - `facility_ids`: 包含的设施ID列表（ARRAY类型）
  - `total_length`: 总长度（公里，numeric(10,3)）
  - `start_stake`: 起始桩号（numeric(10,3)）
  - `end_stake`: 终止桩号（numeric(10,3)）
  - `connectivity_matrix`: 连通性矩阵（JSONB）
  - `bottleneck_analysis`: 瓶颈分析结果（JSONB）
  - `network_metrics`: 网络指标（JSONB）
  - `created_at`: 创建时间（timestamp，默认CURRENT_TIMESTAMP）

### 3.1.1 JSONB字段详解

#### `connectivity_matrix` 字段

- **作用**: 存储路网单元内设施间的连通性关系矩阵
- **数据结构**: 包含设施间连接强度、距离、路径复杂度、质量评分等
- **典型应用**: 网络连通性分析、路径规划、设施间影响评估

#### `bottleneck_analysis` 字段

- **作用**: 存储路网单元的瓶颈分析结果
- **主要内容**:
  - `critical_facilities`: 关键设施列表（设施ID、名称、类型、瓶颈数量、风险评分）
  - `bottleneck_chains`: 瓶颈链路（风险等级、起终点设施、连接类型、风险评分）
  - `cascade_paths`: 级联路径分析
  - `critical_nodes`: 关键节点分析
- **典型应用**: 瓶颈识别、风险预警、网络优化、应急响应规划

#### `network_metrics` 字段

- **作用**: 存储路网单元的综合网络指标
- **主要指标**:
  - `route_code`: 路线代码
  - `stake_range`: 桩号范围
  - `network_type`: 网络类型
  - `total_length`: 总长度
  - `facility_count`: 设施数量
  - `network_density`: 网络密度
  - `bottleneck_metrics`: 瓶颈指标（分析类型、分析记录数）
  - `avg_facility_spacing`: 平均设施间距
  - `connectivity_metrics`: 连通性指标（平均质量评分、总连接数、高质量连接数）
- **典型应用**: 网络性能评估、密度分析、连通性评估、规划决策支持

### 3.4 典型使用方法

```sql
-- 查询路网单元基本信息
SELECT network_id, network_name, network_type, 
       facility_count, total_length,
       array_length(facility_ids, 1) as actual_facility_count
FROM dim.multiscale_network_units
ORDER BY network_type, facility_count DESC;

-- 分析路网连通性
SELECT network_id, network_name,
       (network_metrics->>'network_density')::numeric as density,
       (network_metrics->'connectivity_metrics'->>'total_connections')::int as total_connections,
       (network_metrics->'connectivity_metrics'->>'avg_quality_score')::numeric as avg_quality
FROM dim.multiscale_network_units
WHERE network_metrics->'connectivity_metrics'->>'total_connections' != '0'
ORDER BY density DESC;

-- 查询路网包含的设施详情
SELECT n.network_id, n.network_name, n.network_type,
       f.facility_type, COUNT(*) as facility_count
FROM dim.multiscale_network_units n
LEFT JOIN dim.multiscale_facility_units f ON f.facility_id = ANY(n.facility_ids)
GROUP BY n.network_id, n.network_name, n.network_type, f.facility_type
ORDER BY n.network_id, facility_count DESC;

-- 分析路网瓶颈风险
SELECT network_id, network_name,
       jsonb_array_length(bottleneck_analysis->'bottleneck_chains') as bottleneck_chains_count,
       jsonb_array_length(bottleneck_analysis->'critical_facilities') as critical_facilities_count
FROM dim.multiscale_network_units
WHERE jsonb_array_length(bottleneck_analysis->'bottleneck_chains') > 0
ORDER BY bottleneck_chains_count DESC;

-- 查询高风险瓶颈链路
SELECT network_id, network_name,
       jsonb_array_elements(bottleneck_analysis->'bottleneck_chains') as bottleneck_chain
FROM dim.multiscale_network_units
WHERE (bottleneck_analysis->'bottleneck_chains') IS NOT NULL
  AND jsonb_array_length(bottleneck_analysis->'bottleneck_chains') > 0;

-- 分析路网连通性质量
SELECT network_id, network_name,
       (network_metrics->'connectivity_metrics'->>'avg_quality_score')::numeric as avg_quality,
       (network_metrics->'connectivity_metrics'->>'total_connections')::int as total_connections,
       (network_metrics->'connectivity_metrics'->>'high_quality_connections')::int as high_quality_connections,
       ROUND((network_metrics->'connectivity_metrics'->>'high_quality_connections')::numeric / 
             NULLIF((network_metrics->'connectivity_metrics'->>'total_connections')::numeric, 0) * 100, 2) as quality_ratio
FROM dim.multiscale_network_units
WHERE (network_metrics->'connectivity_metrics'->>'total_connections')::int > 0
ORDER BY avg_quality DESC;
```

## 四、多尺度评估典型应用场景

### 4.1 交通瓶颈识别

```sql
-- 基于节点层识别瓶颈位置
SELECT route_code, node_type, COUNT(*) as bottleneck_count
FROM dim.multiscale_node_units 
WHERE node_type IN ('diverging', 'merging')
  AND junction_id IN (
    -- 这里可以结合交通流数据识别瓶颈节点
    SELECT junction_id FROM traffic_flow_data 
    WHERE congestion_level > 0.8
  )
GROUP BY route_code, node_type;

-- 基于设施层识别瓶颈设施
SELECT facility_id, facility_name, facility_type,
       (facility_metrics->>'bottleneck_score')::numeric as bottleneck_score
FROM dim.multiscale_facility_units
WHERE (facility_metrics->>'bottleneck_score')::numeric > 0.7
ORDER BY bottleneck_score DESC;
```

### 4.2 网络连通性分析

```sql
-- 分析路网层连通性
SELECT network_id, network_name,
       (network_metrics->'connectivity_metrics'->>'total_connections')::int as connections,
       (network_metrics->'connectivity_metrics'->>'avg_quality_score')::numeric as quality,
       (network_metrics->>'avg_facility_spacing')::numeric as avg_spacing
FROM dim.multiscale_network_units
ORDER BY connections DESC;
```

### 4.3 空间覆盖分析

```sql
-- 分析设施空间覆盖
SELECT route_code, facility_type,
       COUNT(*) as count,
       ROUND(SUM(ST_Area(ST_Transform(geometric_boundary, 3857))/1000000)::numeric, 2) as total_area_km2,
       ROUND(AVG(ST_Area(ST_Transform(geometric_boundary, 3857))/1000000)::numeric, 2) as avg_area_km2
FROM dim.multiscale_facility_units
GROUP BY route_code, facility_type
ORDER BY route_code, total_area_km2 DESC;
```

### 4.4 多尺度关联分析

```sql
-- 分析路网-设施-节点的层级关系
WITH network_facility_analysis AS (
  SELECT n.network_id, n.network_name, n.network_type,
         COUNT(f.facility_id) as facility_count,
         SUM(array_length(f.node_ids, 1)) as total_nodes
  FROM dim.multiscale_network_units n
  LEFT JOIN dim.multiscale_facility_units f ON f.facility_id = ANY(n.facility_ids)
  GROUP BY n.network_id, n.network_name, n.network_type
)
SELECT *, 
       ROUND(total_nodes::numeric / facility_count, 1) as avg_nodes_per_facility
FROM network_facility_analysis
ORDER BY total_nodes DESC;
```

## 六、使用建议

### 6.1 查询优化

- 使用空间索引进行几何查询
- 利用GIN索引进行数组和JSONB查询
- 根据分析需求选择合适的尺度层级

### 6.2 分析策略

- **宏观分析**：使用路网层数据进行整体网络评估
- **中观分析**：使用设施层数据进行设施功能评估
- **微观分析**：使用节点层数据进行局部瓶颈识别和车道容量分析

### 6.3 交通管控影响分析应用

**核心应用场景**：这些多尺度分析单元表专门设计用于**仿真结果的交通运行状态分析**，特别适用于评估**事件或管控措施对交通网络的影响**：

#### 6.3.1 管控策略效果评估
- **限速管控**：通过节点层的 `analysis_metrics` 分析速度变化对节点通行能力的影响
- **车道管控**：利用设施层的 `facility_metrics` 评估车道关闭对互通枢纽的影响
- **路径引导**：基于路网层的 `connectivity_matrix` 分析路径变更对整体网络连通性的影响

#### 6.3.2 事件影响分析
- **事故影响**：通过多尺度层级分析事故点对周边节点、设施和路网的影响范围
- **施工影响**：评估施工区域对设施层和路网层通行能力的影响
- **恶劣天气**：分析天气事件对不同尺度交通单元的影响程度

#### 6.3.3 管控优化决策支持
- **瓶颈识别**：利用 `bottleneck_analysis` 字段识别关键瓶颈位置
- **优先级排序**：基于 `facility_rating` 和 `node_health_score` 确定管控优先级
- **效果预测**：通过历史 `analysis_metrics` 数据预测管控措施的效果

### 6.4 扩展应用

- 结合交通流数据进行动态分析
- 集成历史数据进行趋势分析
- 结合其他地理数据进行综合评估
