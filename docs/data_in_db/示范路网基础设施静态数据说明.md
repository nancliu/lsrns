## 表间关系与引用规则

- 示范路线关联（demonstration_*）
  - `dim.point_gantry`、`dim.point_service_zone`、`dim.point_toll_84`、`dim.point_toll_square` 含有 `demonstration_id`/`demonstration_route_code`/`demonstration_route_name` 字段，用于将设施点归并到同一示范路线。
  - `dim.demonstration_route_ref` 可作为示范路线筛选入口（以 `demonstration_id` 或 `demonstration_route_code` 过滤）。

- 收费站与收费广场
  - 主键关联：`dim.point_toll_84.station_code` ↔ `dim.point_toll_square.station_code`（标准编码）。
  - `dim.point_toll_square.direction` 标识入口/出口/双向；`square_code` 建议唯一。

- TAZ 到仿真点映射（关键）
  - `dim.taz_to_simnetwork.square_gantry` 决定 `point_id` 的解释：
    - 为 `gantry` 时：`point_id` ↔ `dim.point_gantry.gantry_id`；
    - 为 `square` 时：`point_id` ↔ `dim.point_toll_square.square_code`。
  - `od_type` 指示 O/D 角色（origin/destination/all）。

- 线路与路段聚合
  - 设施表普遍含 `route_code`/`route_name`，部分含 `section_code`/`section_name`；
  - 用 `route_code` 聚合同线路设施；存在 `section_code` 时可细化到路段级。

### 典型关联 SQL（示例）

- 按示范路线汇总门架与收费广场：
```sql
-- :demo_id 为输入参数
(
  SELECT 'gantry' AS pt_type, g.gantry_id AS pt_id, g.route_code, g.section_code,
         g.gantry_name AS pt_name, g.demonstration_id
  FROM dim.point_gantry g
  WHERE g.demonstration_id = :demo_id
)
UNION ALL
(
  SELECT 'square' AS pt_type, s.square_code AS pt_id, s.route_code, s.section_code,
         s.square_name AS pt_name, s.demonstration_id
  FROM dim.point_toll_square s
  WHERE s.demonstration_id = :demo_id
);
```

- 将 TAZ 映射解析为门架/广场并带出名称与方向：
```sql
SELECT t.point_id,
       t.square_gantry,
       COALESCE(g.gantry_name, s.square_name) AS point_name,
       s.direction,
       t.total_flow,
       COALESCE(g.route_code, s.route_code) AS route_code
FROM dim.taz_to_simnetwork t
LEFT JOIN dim.point_gantry g
  ON t.square_gantry = 'gantry' AND t.point_id = g.gantry_id
LEFT JOIN dim.point_toll_square s
  ON t.square_gantry = 'square' AND t.point_id = s.square_code;
```

- 收费站与收费广场关联（仅使用标准编码）：
```sql
SELECT tz.station_code, tz.station_name,
       sq.square_code, sq.square_name, sq.direction
FROM dim.point_toll_84 tz
LEFT JOIN dim.point_toll_square sq
  ON sq.station_code = tz.station_code;
```

- 按线路聚合各类设施数量：
```sql
SELECT route_code,
       COUNT(DISTINCT gantry_id) AS gantry_cnt,
       COUNT(DISTINCT station_code) AS toll_station_cnt,
       COUNT(DISTINCT square_code) AS toll_square_cnt,
       COUNT(DISTINCT service_area_code) AS service_area_cnt
FROM (
  SELECT route_code, gantry_id, NULL::text AS station_code, NULL::text AS square_code, NULL::text AS service_area_code FROM dim.point_gantry
  UNION ALL
  SELECT route_code, NULL, station_code, NULL, NULL FROM dim.point_toll_84
  UNION ALL
  SELECT route_code, NULL, NULL, square_code, NULL FROM dim.point_toll_square
  UNION ALL
  SELECT route_code, NULL, NULL, NULL, service_area_code FROM dim.point_service_zone
) u
GROUP BY route_code;
```

### 建议的主键/唯一性（若库内未显式约束）

- `dim.point_gantry.gantry_id`：唯一。
- `dim.point_toll_square.square_code`：唯一。
- `dim.point_toll_84.station_code`：唯一（收费站主键）。
- `dim.point_toll_84.station_code_js`：别名字段，不参与关联。
- `dim.point_service_zone.service_area_code`：唯一。
- `dim.taz_to_simnetwork.point_id`：建议唯一（同一 `square_gantry` 下不重复）。

> 提醒：包含大写的标识符在 SQL 中需用双引号包裹以避免大小写敏感问题。

---

- **统一规范建议**:
  - **坐标字段**: 统一以 `lng_84`/`lat_84` 为主坐标，其他坐标系字段保留用于校验或转换。
  - **编码字段**: `route_code`、`section_code`、`station_code` 等应保持唯一性与稳定性；如涉及大小写，SQL 中务必使用双引号引用含大写的标识符以避免大小写敏感问题。
  - **约束与索引**: 建议对主键/唯一键与常用查询条件建立索引（如 `station_code`、`square_code`、`gantry_id`）。
