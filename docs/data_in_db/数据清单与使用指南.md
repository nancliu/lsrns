## 二、核心数据表清单

### 2.1 仿真输入数据（Initial Conditions）

| 序号 | 数据表 | 记录数 | 用途 | 关键字段 |
|------|--------|--------|------|----------|

## 三、仿真应用流程

### 3.1 仿真初始化（第1步：路网构建）

```sql
-- Step 1: 加载SUMO路网边缘
SELECT id AS edge_id,
       "from" AS from_junction,
       "to" AS to_junction,
       length,
       lanes,
       speed AS max_speed
FROM dim.sim_network_edges;

-- Step 2: 加载SUMO路网节点
SELECT id AS junction_id,
       type AS node_type,
       ST_X(geometry) AS lon,
       ST_Y(geometry) AS lat
FROM dim.sim_network_junctions;

-- Step 3: 门架-路段映射（用于检测器布设）
SELECT gantry_id,
       stake_number,
       route_code,
       gantry_name
FROM dim.all_gantry_228
ORDER BY route_code, stake_number;
```

### 3.2 流量注入配置（第2步：需求生成）

#### 3.2.1 门架流量注入（分时段）

```sql
-- 查询工作日早高峰（7-9点）门架流量
SELECT
    gantry_id,
    hour,
    mean AS avg_flow_per_5min,
    p85 AS p85_flow_per_5min,
    p95 AS p95_flow_per_5min,
    truck_ratio,
    passenger_small,
    passenger_large,
    truck_small,
    truck_large,
    avg_speed,
    free_flow_speed
FROM baseline.baseflow_pattern_gantry
WHERE pattern_type = 'workday'
  AND hour BETWEEN 7 AND 9
ORDER BY gantry_id, hour;
```

**使用建议**：
- `mean` - 常规场景流量注入
- `p85` - 接近峰值场景（容量估算基准）
- `p95` - 极端峰值场景（应急管控测试）
- `truck_ratio` - 车型生成比例

#### 3.2.2 OD流量需求（路径选择）

```sql
-- 查询Top-100热点OD对（工作日早高峰8点）
```

### 3.3 管控策略建模（第3步：策略实施）

**策略参数**：

- 限速值：基于 `free_flow_speed` 下调10-30 km/h
- 管控时段：基于 `congestion_hours` 识别拥堵时段

```sql

    entity_id AS gantry_id,
    pattern_type,
    congestion_hours,
    free_flow_speed,
    speed_std
FROM highway.batch_kpi_summary
WHERE dimension = 'gantry'
  AND pattern_type = 'workday'
  AND congestion_hours >= 2
ORDER BY congestion_hours DESC;
```

#### 3.4.2 管控后效果计算

**评估指标**：
1. **行程时间变化** = (仿真MTT - baseline_mtt) / baseline_mtt × 100%
2. **速度提升** = (仿真Speed - baseline_speed) / baseline_speed × 100%
3. **流量平滑度** = 仿真Flow_CV vs. 历史Flow_CV
4. **拥堵缓解** = (baseline_congestion_hours - 仿真congestion_hours)

**显著性检验**：
- 偏离基线 > 2σ → 效果显著
- t检验（样本量 >= 30）
- 置信区间：95%

```sql
-- 示例：计算偏离标准差倍数
SELECT
    entity_id,
    (仿真mtt - mtt_baseline_mean) / NULLIF(mtt_baseline_std, 0) AS deviation_sigma,
    CASE
        WHEN ABS((仿真mtt - mtt_baseline_mean) / NULLIF(mtt_baseline_std, 0)) > 2
        THEN '效果显著'
        ELSE '效果不显著'
    END AS significance
FROM highway.historical_baseline
WHERE dimension = 'gantry'
  AND pattern_type = 'workday';
```

### 3.5 校准验证（第5步：精度检查）

#### 3.5.1 流量对比（RMSE/MAPE）

```sql
-- 获取真实观测流量（5分钟粒度）
SELECT
    start_gantryid AS gantry_id,
    start_time,
    total AS observed_flow,
    total_h AS observed_truck_flow,
    avg_speed AS observed_speed
FROM dwd.dwd_flow_gantry_weekly
WHERE start_time BETWEEN '2025-09-22 07:00:00' AND '2025-09-22 09:00:00'
  AND start_gantryid = 'G000551001000110010'
ORDER BY start_time;
```

**精度计算公式**：
- RMSE = √(Σ(仿真值 - 观测值)² / n)
- MAPE = Σ|仿真值 - 观测值| / 观测值 / n × 100%
- GEH = √(2×(仿真值 - 观测值)² / (仿真值 + 观测值))

**验收标准**：
- MAPE < 15% → 优秀
- GEH < 5（85%样本点） → 合格

---

#### 3.5.2 路径长度验证

```sql
-- 对比仿真路径与SUMO参考距离
SELECT
    origin_id,
    destination_id,
    sumo_distance_km AS reference_distance,
    仿真路径长度_km AS simulated_distance,
    ABS(仿真路径长度_km - sumo_distance_km) / sumo_distance_km * 100 AS error_pct
FROM highway.od_route_distance
WHERE distance_source = 'sumo'  -- 仅使用SUMO精确计算的距离
ORDER BY error_pct DESC
LIMIT 20;
```

**验收标准**：
- 路径长度误差 < 5% → 合格
- Top-100 OD对误差均值 < 3% → 优秀

## 五、典型仿真场景配置

### 场景A：工作日早高峰限速管控

**目标**：缓解7-9点拥堵，提升平均速度

**数据配置**：
```sql
-- 1. 流量输入（工作日7-9点）
SELECT * FROM baseline.baseflow_pattern_gantry
WHERE pattern_type = 'workday' AND hour BETWEEN 7 AND 9;

-- 2. 拥堵路段识别
SELECT entity_id, congestion_hours, free_flow_speed

WHERE dimension = 'gantry' AND pattern_type = 'workday'
  AND congestion_hours >= 2;

-- 3. 基线对比
SELECT entity_id, speed_baseline_mean, speed_upper_threshold
FROM highway.historical_baseline
WHERE dimension = 'gantry' AND pattern_type = 'workday';
```

**管控策略**：
- 限速值：80 km/h（原120 km/h）
- 管控路段：拥堵小时数 >= 2的路段
- 管控时段：7:00-9:00

**评估指标**：
- 主要：平均速度提升 > 5%
- 次要：拥堵小时数减少 >= 1小时
- 验证：GEH < 5（流量匹配度）

## 七、常见问题（FAQ）

### Q1: 如何选择合适的流量分位数？

**A1**:
- **P50（中位数）**: 常规场景，代表典型流量水平
- **P85**: 接近峰值，适合容量估算（HCM推荐）
- **P95**: 极端峰值，应急管控测试
- **均值（mean）**: 平滑数据，适合长期趋势分析

**推荐**：
- 仿真流量注入：使用 `mean` 或 `p50`
- 容量计算：使用 `p85`
- 极端场景测试：使用 `p95`

---

### Q2: 为什么部分OD对没有速度数据？

**A2**: 速度数据仅在**门架维度**有效，OD维度使用**行程时间**（`avg_travel_time`）替代。

**转换公式**：
```
平均速度 = 距离 / 行程时间
         = od_route_distance.sumo_distance_km / (avg_travel_time / 3600) [km/h]
```

---

### Q3: 如何处理 `holiday_free` 模式数据缺失？

**A3**: 部分 `holiday_free` 数据通过 `workday` 插值生成（`sample_count = 0`标记）。

**处理方法**：
1. **优先使用原始数据**（`sample_count > 0`）
2. **次选补充数据**（`sample_count = 0`），加权系数0.8
3. **最后使用工作日数据** × 1.5系数（春节/国庆经验值）

```sql
SELECT *,
       CASE WHEN sample_count = 0 THEN 'supplemented' ELSE 'original' END AS data_source
FROM baseline.baseflow_pattern_gantry
WHERE pattern_type = 'holiday_free';
```

---

### Q4: 批次数据的时间范围是什么？

**A4**: 每个批次覆盖一周（7天），命名格式 `YYYYMMDD_YYYYMMDD`。

**示例**：
- `20250922_20250928` = 2025年9月22日至9月28日
- 共16批次，覆盖2025年6月9日至9月28日（约3个月）

**批次连续性检查**：
```sql
SELECT batch_id,
       LAG(batch_id) OVER (ORDER BY batch_id) AS prev_batch,
       TO_DATE(SUBSTRING(batch_id, 1, 8), 'YYYYMMDD') -
       TO_DATE(SUBSTRING(LAG(batch_id) OVER (ORDER BY batch_id), 10, 8), 'YYYYMMDD') AS gap_days
FROM (SELECT DISTINCT batch_id FROM highway.batch_kpi_summary) t
ORDER BY batch_id;
```

---

### Q5: 如何验证仿真结果的可信度？

**A5**: 三步验证法：

**Step 1: 流量匹配（GEH指标）**
```
GEH = √(2×(仿真-观测)² / (仿真+观测))
验收标准：85%样本点 GEH < 5
```

**Step 2: 速度对比（MAPE）**
```
MAPE = Σ|仿真-观测| / 观测 / n × 100%
验收标准：MAPE < 15%
```

**Step 3: 显著性检验（与历史基线对比）**
```
偏离σ = (仿真KPI - 基线均值) / 基线标准差
显著性：|偏离σ| > 2 → 效果显著
```

---

### Q6: 如何使用DWD层数据进行仿真校准？

**A6**: DWD层提供真实观测数据用于仿真校准：

**数据表选择**：

```sql
FROM dwd.dwd_flow_gantry_weekly

```

**详细说明**: 参见《DWD_Tables_Usage_Guide.md》第3节
