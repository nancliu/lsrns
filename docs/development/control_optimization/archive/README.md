## 归档原则

### 何时归档
1. 文档内容已被新文档完全替代
2. 原型代码已演进为正式实现
3. 测试数据已有更新的验证结果
4. 临时草稿已整合到正式文档

### 归档 vs 删除
- **归档**: 保留有历史参考价值的文件（原型代码、早期设计思路、重要测试数据）
- **删除**: 完全无价值的临时文件（重复副本、错误数据、测试垃圾文件）

### 如何使用归档
- 查阅历史设计思路和演进过程
- 对比当前实现与早期原型的差异
- 恢复或参考早期的测试数据
