## 🚀 快速开始

### 新开发者入门

1. **了解项目背景**:
   - 阅读 [管控方案优化子系统PRD文档.md](./管控方案优化子系统PRD文档.md) - 了解目标和范围
   - 阅读 [管控方案优化子系统架构设计方案.md](./管控方案优化子系统架构设计方案.md) - 理解技术架构

2. **查看当前进展**:
   - 阅读 [Epic1_完成报告.md](./Epic1_完成报告.md) - 了解已完成的工作
   - 阅读 [MVP功能清单.md](./MVP功能清单.md) - 了解功能实现状态

3. **开始开发**:
   - 查看 [TODO.md](./TODO.md) - 获取待办任务列表
   - 选择任务并开始编码

### 测试人员入门

1. **阅读测试指南**:
   - [MVP测试指南.md](./MVP测试指南.md) - 了解测试流程和验收标准

2. **运行手动测试**:
   - 参考 [tests/manual/README.md](../../../tests/manual/README.md)
   - 启动服务器并执行测试脚本

3. **查看测试结果**:
   - 检查 `cases/*/control_optimization/` 目录中的输出文件
   - 验证性能指标是否达标

## 📝 文档维护规范

### 更新频率
- **TODO.md**: 每个任务开始/完成时更新
- **MVP功能清单.md**: 每个功能模块完成时更新
- **Epic完成报告**: 每个Epic完成时创建
- **PRD/架构文档**: 重大变更时更新（版本号递增）

### 文件命名规范
- 规划文档: `{模块名称}{文档类型}.md` (如 `管控方案优化子系统PRD文档.md`)
- 报告文档: `Epic{N}_{完成|进度}报告.md`
- 指南文档: `{功能名称}{指南|清单|测试}.md`

### 归档规则
- 过时的测试总结 → `archive/`
- 原型代码和测试数据 → `archive/`
- 保留归档文件，便于查阅历史
