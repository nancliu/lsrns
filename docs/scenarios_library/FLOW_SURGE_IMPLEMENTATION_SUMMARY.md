# 流量激增场景实施总结

## 概述

成功实现流量激增工况场景提取功能，将高流量时段事件纳入事件场景库。流量激增作为"工况"而非"突发事件"，为评估日常高峰期控制策略提供测试场景。

**实施日期**: 2025-11-14
**版本**: v1.0.0
**状态**: ✅ 测试通过

---

## 实施方案

### 方案选择

采用**方案B：扩展为"流量高峰时段场景"**，保持MVP架构，为未来"交通工况维度"扩展预留空间。

### 核心决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| **事件类型名称** | "流量激增工况" | 强调工况属性，区别于突发事件 |
| **时长筛选标准** | ≥30分钟 | 原始事件10-25分钟过短，筛选后获得15个符合要求的事件 |
| **场景对比方式** | 仅对比不同控制策略 | 不对比baseline（流量已在OD数据中） |
| **目录组织** | `07_flowsurge/` | 独立目录，便于未来扩展更多工况类型 |
| **SUMO注入方式** | CongestionInjector（无XML） | 流量体现在OD数据中，无需物理注入 |
| **影响粒度** | 整个edge | 不精细到lane级别 |

## 与现有事件体系的对比

| 维度 | 传统事件（事故/管制） | 流量激增工况 |
|------|---------------------|-------------|
| **事件性质** | 突发扰动 | 周期性工况 |
| **SUMO注入** | closedLane等物理元素 | 无XML注入 |
| **影响机制** | 车道封闭→通行能力下降 | OD流量增加→需求增加 |
| **空间定位** | edge + lanes精确定位 | edge级别（无lane精度） |
| **时长特征** | 0.5-3小时（推荐1-2h） | 0.5-0.75小时（30-45分钟） |
| **baseline对比** | 可对比（有/无事件） | **不对比**（流量已在OD中） |
| **评估重点** | 控制策略响应效果 | 不同策略流量疏导效果 |
| **典型控制策略** | VSS、DHS、TEC | VSS、DHS（早高峰）、TEC |
